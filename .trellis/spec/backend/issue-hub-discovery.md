# Issue仓库固定发现范围（YG 0.3.4）

## 1. 范围与触发

用户2026-11-05明确将扫描边界定义为产品特性，取消对用户展示项目发现“不完整”机制。此约定覆盖旧菜单partial警示要求。修改catalog、项目发现展示或诊断时读取；Issue/评论/活动分页及会话候选覆盖仍沿用原契约。

## 2. 签名

- `discoverGitRepositories(directory,{gitInspector=inspectGit,maxDepth=3,maxDirectories=1500})`。
- `createCatalog({bridge,...}).refresh({quick?})`仍从既有`project/list`取得工作区。
- `inspectGit(directory)`仍通过Git自身核验实际仓库与GitHub remote，不新增任意命令/路径接口。

## 3. 行为与响应契约

- 已登记root深度0，优先核验自身Git信息；即使项目指向仓库子目录，也保留实际cwd不扩大授权范围。根无法访问的真实异常保留。
- root下默认最多检查深度1/2/3。子目录通过.git标记筛选，再交Git核验，兼容.git目录及worktree/submodule使用的.git文件；不自行解析config，不枚举GitHub账号全部仓库。
- 第3层仍检查仓库标记，但不枚举其下子目录。深度4及以上不属于默认范围，单独登记的更深root仍直接核验。不能遇见第一个仓库即停止所有嵌套搜索。
- 保留1500目录保护、依赖/构建目录排除、链接与根范围限制、多root合并以及原仓库/工作区键算法。
- 正常深度结束不生成DIRECTORY_DEPTH_LIMIT。内部partial/warnings继续兼容旧缓存、真实异常与守卫；不强改实际失败为complete，不丢失已发现仓库。
- 用户菜单移除发现状态行、警示点以及title/aria中的覆盖描述，项目空态不称发现“不完整”。诊断过滤正常扫描边界、链接排除及缓存进度提示，具体ROOT/GIT问题保留安全中文说明，不显示原始私有路径或异常串。

## 4. 校验与错误

| 场景 | 行为 |
| --- | --- |
| 默认深度3已检查 | 正常结束，不提示扩大范围 |
| 深度4仓库未登记 | 不属于默认搜索范围；无“不完整”提示 |
| 深度4目录单独登记 | 作为新root直接核验 |
| 单个root缺失或Git读取失败 | 保留安全诊断，其他已发现仓库正常使用 |
| 宿主项目接口不可用/身份失效 | 沿用实际错误、缓存资格及任务保护，不伪造成功 |
| 旧快照有深度/数量边界warning | 菜单不恢复警示，诊断不把固定范围当待修问题 |

## 5. 正常、基础与失败场景

正常：登记Git根与3层内的独立嵌套仓库都可发现；worktree.git文件按Git自身识别。基础：只显示现有范围内仓库，无覆盖状态组件。失败：root不能读取时连接检查说明具体类型，不能用取消覆盖提示绕过创建任务时的工作区核对。

## 6. 必须验证

真实临时Git仓库覆盖3/4层边界、深根单独登记、根优先、worktree及排除项；菜单覆盖null/loading/checking/partial/unavailable和旧警告输入均无状态行/点；诊断固定边界无泛化覆盖提示、具体Git/目录错误保留。完整Issue回归与语法、统一包协议、真实只读发现前后仓库比较、浏览器菜单和诊断分别记录，不冒充Codex原生UI验证。

## 7. 错误与正确做法

错误：只提高扫描上限，继续要求用户处理不可操作的覆盖警告；或为消除提示把真实宿主/权限失败强写成成功。

正确：明确固定发现范围，根优先、3层标记候选与Git验证；移除面向用户的覆盖机制，保留具体故障和原身份/工作区守卫。

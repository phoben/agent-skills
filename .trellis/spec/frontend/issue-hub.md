# Issue Hub 页面与原型交接

## 1. 适用范围

修改 `packages/issue-hub/ui/` 时读取。2026-11-04 用户已确认 A 连读队列完整原型，正式页面使用其布局；`proof.mjs` 只为P0兼容测试保留，不是正式入口。不套用 Tokens C 版布局，不再询问整体开工批准。

当前Issue Hub作为YG Toolkit模块交付。统一的是安装包与插件版本，Tokens/Issue各保留页面；不重新设计已确认的A布局，不变更已有工具或UI URI。源码私有package版本不承担安装/显示版本。迁移验证保留原草稿/偏好/关联，不因包ID变化初始化新业务目录。

用户已明确选择首版使用单主入口加页面内仓库导航，并另行确认完整原型。主画布1120×880，窄窗960×680；浅深主题、焦点和主要交互沿用基线。已确认方向与验收范围见[架构](../../../docs/issue-hub/architecture.md)和[验收](../../../docs/issue-hub/acceptance.md)；原型截图及本机执行记录留本地，未验证的动效手感不写成通过。

## 正式页面契约（0.2.0）

- App连接后用固定query/mutate/task工具，读取envelope的schemaVersion/identity/data；LiveStore只保存当前投影，持久缓存、草稿、偏好由后端SQLite负责。正式包无fixture、场景开关、原型目录、CDN或localhost依赖。
- 宿主主题通过hostContext；启动通知不能覆盖已经开始的显式读取。所有异步结果关联账号、仓库、Issue代次。写入及任务请求携带expectedIdentity；身份变化先清除旧私有视图和在途投影，再读新身份。
- `cached`不能当离线；明确offline决定GitHub联网状态。task恢复不更新最后GitHub成功时间，也不把离线重置在线。未加载、不可访问或部分覆盖不能补零/显示空仓库；仓库名称保留owner避免同名混淆。
- 分页列表和详情的字段归属分开，轮询不得用列表中的空commentItems覆盖已读讨论。revision变化且有编辑输入时保留讨论并标旧投影，完成编辑后由显式详情读取清除标记；列表翻页不能删除当前选中详情。
- 草稿导航保存串行，保存失败阻止离开并保留输入；多行Enter不发布。恢复网络只读取，不自动发布。已发现远端冲突比较后再保存；未知写入先核对GitHub，人工解除只允许下次主动提交，已接受后读回失败只重读。
- 远端Markdown统一转义、危险协议拒绝、图片链接化。PR/附件使用真实受校验链接，经宿主openLink打开，不把正文中的指令转成宿主操作。作者编辑与属性管理权限分开，标题编辑不改未变元数据。
- 任务按钮只调用真实latest/open/check，不模拟发送或猜测thread。一个有效工作区单击预填，不自动发送；open-unconfirmed显示核对打开结果，不能写成创建成功。另建明确且不覆盖已有请求。
- 60秒轮询仅前台当前仓库；编辑/保存时保留输入，保存中不并发刷新。关键键盘/身份/分页/草稿/未知恢复和投影归属须有有效回归，浏览器真实入口到可观察结果另验。

## 2. 签名

### 0.3.0 会话管理与自动同步

- 0.3.4来源区域明确区分附件暂无/正文未读及PR活动未读/部分/不可用/完整暂无。首批和后页活动按真实sourceIsPr/sourceUrl派生去重relatedPr，coverage.loaded累计已加载条数，不能只保留最后一页计数。
- hydrateIssue首批活动及显式more-activity完成后复用summaryPainter局部更新来源，不重建评论或编辑表单。分页控件自己的焦点可在显式翻页时替换，结束回下一页按钮或活动标签；其他讨论控件焦点继续保护。异步完成复核原repo/Issue/identity，不把旧结果绘制到新详情。
- 来源回归需覆盖PR只出现在第2页、初批活动迟到、空/部分/不可用/危险链接、聚焦分页按钮、评论节点保留和切Issue。正式浏览器抽查实际空态及主题，真实API读取和受控分页样例分别标明。

- 0.3.2新增 `LiveStore.prepareTask()`：目录refreshNeeded/checking/unavailable时使用正常query.refresh更新页面目录投影，完成后复核generation和identity；失败或仍待核查时不open。显式创建首次latest前调用，createTask/bind也保护直接调用者；即使prepareTask立即返回，操作级仍在await前后复核身份与代次。只有query的真实联网证据才能解除离线，CATALOG_CHECKING本身不代表GitHub离线。
- 创建任务从首次核对起显示“正在核对工作区…”，设置disabled/aria-busy；连续误点复用进行中意图，不重复准备。成功自动继续本次动作；失败恢复按钮并保留输入，不要求用户靠下一次点击补全准备。测试须执行实际控制器和按钮绘制，覆盖准备前未决promise、重复点击及结束恢复。
- 显式创建在点击时捕获仓库/Issue/账号；preserveBefore、flushDrafts及prepareTask等await之后都核对原对象，不能等保存完成才捕获新对象。保存期间切仓库、Issue或账号，旧动作应终止且finally恢复按钮，不调用createTask/open。

- task-views提供修改有效工作区绑定、历史和歧义候选弹层。bind成功仅保存后续默认路径，不创建聊天；已有聊天原路径保持可见。历史仅linked可返回；候选无默认选择，服务保存并再核验后才确认。异步结果须校验身份/对象/弹层代次。
- 当前请求的返回发送reuseOnly=true及精确requestId，首次或另建发送false；不能用服务“未找到就新建”掩盖账号切换。显示的reference是实际nonce首行，不能显示requestId冒充验证引用。
- 项目栏、窄窗抽屉和加载失败页均可打开连接检查，不以成功bootstrap为前提。只显示安全白名单字段；discovery状态翻译中文，warnings读取中文string[]，检查中与部分覆盖分开。
- saveIssue/saveComment/changeState拿到confirmed但issue:null时保留成功operation与原输入，只给“仅重新读取”；连续空投影仍保留回执，不邀请再次提交。首次unknown/readback-failed保持原恢复流程。
- 自动strict read-summary成功也须绘制详情，不能仅更新列表，不能以manual或cached决定是否绘制。summary.mjs局部更新标题、正文、属性和链接，保留评论输入、选区、焦点与滚动；未变化正文不替换。H1程序焦点不阻塞更新，正在操作的正文区域可单独延后。
- Issue编辑表单保留输入并提示远端变化；评论草稿不阻止只读摘要更新。局部绘制复核state.saving，避免轮询先发出、写入随后开始时旧响应盖掉提交过程。
- 回归直接执行实际控制器：返回reuseOnly开关、绑定不创建、历史/候选代次、连接失败入口、confirmed连续空投影、自动摘要更新与评论节点保留、在途轮询遇写入。真实浏览器另验60秒下次检查可见且草稿保留，不能拿手动刷新代替。

### 0.2.3 宿主主题与品牌

- `createThemeController`接入App初始hostContext和onhostcontextchanged。显式宿主light/dark优先系统偏好，无宿主时才跟随系统；切主题清遗留变量，同主题支持增量，空变量对象清理，close时释放监听。
- CSS优先映射SDK的color-background/text/border、danger/warning及shadow语义变量；无宿主变量时使用中性白灰/炭黑回退。普通按钮、选择、焦点和分割线保持中性，不将success/accent绿色作为全局主色。颜色读取验收等按钮背景过渡结束，不能把切换首帧当最终对比度。
- 插件资产`assets/icon.svg`、favicon和页面brand使用同一双票据连接轮廓；双清单composerIcon/logo保持同一引用。页面mark使用currentColor；Issue自身的状态图标不随品牌更换。
- 原生global入口还需要公开MCP serverInfo.icons，不能只更换插件文件。main/preview从实际asset构造亮暗内联SVG，包外与安装后逐字回读；当前SDK省略可选Tool.icons时不使用私有注册表或处理器装饰去强填。
- 主题生命周期4项回归验证host与OS相反、切换清旧变量、同主题增量/清空及系统回退；实际浏览器另查浅深/宿主自定义token和16/24/32小图标，不以XML解析代替看图。

### 0.2.1 列宽与渐进交互

- `layout.mjs`通过CSS变量控制列宽，项目栏164–420、Issue栏280–640，并给详情保留至少360；窄窗继续抽屉/单详情。separator有role/aria、pointer capture/取消、方向键16（Shift48）、Home/End与Enter恢复；结束后写view-state，拖动不重建表单、不发GitHub请求。
- 列宽与上次选仓来自当前scope SQLite，不依赖iframe localStorage。延迟保存不能覆盖新账号偏好；raw/sourceKeys→规范仓库键时迁移投影并保留selected/输入，后台归一不能把用户新选择跳回首仓。
- 单击同步标选择/骨架，非必要偏好后台保存。若有待存草稿，失败保留输入并阻止丢失；保存期间点回当前项会取消待切目标，而读取中的重复点击只复用请求。
- 直接消费已到达的初始bootstrap，不重复读目录。先cache-first列表/read-summary正文，候选、评论、活动和task.latest后台分区更新，未加载讨论不能显示为零。cache/checking/纯本机请求不更新GitHub成功时间。
- 仓库访问代次、Issue写入代次、任务代次分别防迟到结果；旧列表不覆盖刚创建/已读回Issue，旧摘要不复活失权数据，旧评论或latest不盖新写入和新任务。
- 目录不可用的后台响应保留可信当前仓库/详情并显示待核对，HOST_*只影响宿主相关状态，不清GH页或假装GitHub断网；真实GH身份与失权仍清旧投影。
- 体验回归直接执行控制器的未决promise路径，不能只测按钮绑定click字符串；真实浏览器另验拖动/键盘边界、三轮刷新记忆、单击与草稿保留。

- 先 `await app.connect()`，再 `app.callServerTool({name, arguments})`。
- `app.ontoolresult` 接收入仓库的初始上下文；`getHostContext()` 与宿主上下文变化处理主题。
- 正式入口资源为 `ui://issue-hub/app.html`，所有仓库共享资源；P0兼容测试保留host-proof URI，正式main不注册它。不能依赖URL中自造仓库状态。

## 3. 数据与状态

- 以 `structuredContent` 为数据，检查 `isError` 及安全错误，不将失败响应画成成功。
- 初始工具结果可在 connect/status 查询期间抵达；用上下文修订号或同等机制拒绝迟到状态覆盖选中的仓库。
- 仓库/工作区变化时清理旧请求显示；准备、打开、检查及恢复的异步结果都不得覆盖另一个作用域。
- 页面可能因打开聊天被销毁，不能只用内存保存请求。重开后按当前仓库、工作区和身份恢复本插件已有请求，再继续检查；恢复不读取聊天正文。
- 重复误点禁用在途动作；已有请求显示 prepared/requested/waiting/linked/ambiguous 等真实状态，只有 linked 才显示可返回关联。
- 文本和 Git 目录使用 textContent 或表单值，不能把远端或路径拼入 HTML。技术页说明不迁移到正式产品流程。

## 4. 校验与错误

| 条件 | 页面结果 |
| --- | --- |
| 连接关闭 | 提示重新打开，不继续宣称工具可用。 |
| isError 或错误结构 | 显示错误并保留可恢复输入，不写成功状态。 |
| 迟到响应属于旧仓库/工作区 | 丢弃，保留当前上下文。 |
| 没有可恢复自有请求 | 明确没有请求，不自动认领其他身份记录或新建草稿。 |
| 打开结果不确定或关联待定 | 提示用户检查与重试核实，不连续自动开聊天。 |
| 已明确失权且仓库仍在同名目录 | 清读取投影、计数未知、隐藏旧详情；未发输入存原scope草稿，不把它画成可访问远端数据。 |
| 列表刷新且有评论草稿 | 保留讨论投影，revision变化标旧投影，不用空数组清空评论。 |
| metadata在线缓存命中或task恢复 | 不据cached推断离线，task不更新GitHub最后成功时间。 |

## 5. 正常、基础与失败场景

正常：从受控的仓库诊断上下文进入时，标题和工作区对应；发送验证消息后重新回页能恢复并检查请求。诊断工具不算原生仓库导航；插件主图标只有一个。

基础：从状态入口进入可看覆盖数量；没有选中仓库时不伪造工作区，也不允许准备任务。

失败：先到达真实入口结果、后返回空 status 时，不能清掉仓库；请求在途切仓库后不能把旧 prompt 或 thread 显示到新仓库。

## 6. 必须验证

- 隔离 UI 模块测试覆盖初始结果竞争、切换作用域、页面重建后的恢复与继续检查，不只检查静态 HTML 包含文案。
- 包外资源与独立宿主发现检查只能证明资源可读，不能声称已看过实际 Codex 页面。
- 独立原型预览必须实际加载浏览器模块。Windows 静态服务曾将 `.mjs` 返回 text/plain，语法检查虽通过但页面不启动；用本任务预览服务显式映射 text/javascript，不改系统注册表或把接口故障伪装成空数据。
- U1 已完成方向选择、原型截图、独立视觉与UX及用户确认；正式实现继续检查1120×880、960×680和浅深主题，长标题/评论与关键失败状态分别验证，真实宿主另验。

## 7. 错误与正确做法

错误：用最后返回的响应覆盖当前页面，或重开页面丢失请求后让用户反复创建草稿。

同样错误：把主页多个 global 图标当用户要求的原生悬浮栏，或将页面内自绘列表叫作“原生”。原型必须标明宿主能力约束，不以改称呼掩盖缺失。

正确：所有异步结果关联当前上下文，持久请求由受控后端恢复；请求已发出不等于聊天已创建，原型通过不等于 GitHub 集成通过。

# Issue Hub UI 事实包

日期：2026-11-03。此包只给出已确认事实和约束，不指定视觉方向，也不夹带主 Agent 推荐或标杆画面。

## 用户与任务

- Windows Codex 桌面端的开发团队，每天反复查看和处理多个 github.com 仓库的 Issue。
- 唯一插件主图标进入页面后，通过插件页面内导航切仓库。这是用户本轮明确接受的范围；原生悬浮栏不属于本次承诺。
- 仓库来自本机 Codex 项目与 Git remote，可能同仓库对应多个 clone/worktree。创建聊天时单路径直接使用、多路径首次选择后记住，失效时重新选择。
- 主页面必须是 Issue 列表，可看详情及全部分页评论、活动、附件链接、关联 PR。
- 管理范围：新增、标题正文编辑、关闭/重开、新增和编辑本人评论、已有标签增删、负责人和里程碑调整。仓库标签定义和删除操作留 GitHub。
- 点击任务入口优先返回已有确认关联，保留另建；新聊天只预填，成员发送后开始分析、实施及验证。未发送草稿、已发请求和真实已关联不能混淆。
- 新任务入口文案为“创建任务”，已有明确关联时为“返回会话”。只有一个有效工作区时，一次点击即准备并打开预填草稿，不拆成“准备”和“打开”两个操作；首次多路径选择才需要确认绑定。

## 数据与状态

- 每人复用本机 gh 权限，无团队后台；偏好、草稿和聊天关联仅在本机。
- 打开页面立即刷新，当前仓库前台每 60 秒检查；写后读回，有手动刷新及最后成功时间。
- 离线可看已有缓存、写正文或评论草稿，恢复后手动提交。保存失败保留输入，远端冲突需明确处理，不自动覆盖草稿。
- 无数据、筛选为空、未加载全部评论、权限不足、账号变化、限流、断网和失败需区分，不统一补零。
- 账号变化立即清除旧账号私有视图和在途响应，本地缓存与草稿按身份隔离；不能在新账号页面继续展示旧账号缓存，仅停止写入并不足够。
- 页面原型使用确定性测试内容；不得写真实 GitHub、自动打开或发送真实聊天，不将演示成功当远端验收。

## 主角与主动作

- 列表：主角为 Issue 集合，主动作打开一个 Issue；新增、筛选、刷新为低于当前阅读焦点的辅助动作。
- 详情：主角为选中 Issue 的正文和讨论，主动作进入处理它的已有/新聊天；编辑、标签与关闭等须可达但不同时做成同权重主按钮。
- 编辑：主角为待发布内容，主动作保存；错误和冲突不夺走输入。
- 评论：主角为当前输入，主动作发表评论。
- 工作区确认：主角为目标本地工作区，主动作确认绑定。

## 删除、合并与保留

| 元素 | 处理及理由 |
| --- | --- |
| 多个宿主插件图标、仿原生浮层 | 删除；唯一主入口已经确认。 |
| 大号品牌标题、欢迎语、总览指标卡和图表 | 删除；高频处理工作区不需要营销首屏。 |
| 仓库名反复出现在多层头部 | 合并；上下文应清楚但不占掉 Issue 可视区域。 |
| 等权重的新增、编辑、关闭、评论、创建任务按钮 | 按屏幕/状态降级与收纳；主动作唯一。 |
| Issue 编号、状态、标题、标签、负责人和更新信息 | 保留并分层；用于识别与筛选，不靠全彩卡片堆叠。 |
| 同步时间、草稿和未确认会话状态 | 保留；用户必须判断看到的是何时数据、内容是否已发布。 |
| 长正文和评论、完整分页 | 保留；不能为了漂亮首屏裁掉业务信息。 |

## 设备、语言与实现

- 宿主窗口验证 1440×1000 和 1280×800；实际插件画布须减去宿主原生主导航及边框，不让设计依赖全屏无限宽度。
- 中文操作文案，产品名 Issue Hub，仓库/标签及代码标识可英文。专业工具可密集，但不靠极小字体装内容。
- 浅深主题跟随宿主。使用本地系统字体、可自包含的 CSS/SVG 和现有 MCP Apps 桥接；不依赖付费素材、远程 CDN、商业字体或图片生成。
- 可以用对象本身的列表行、讨论结构、任务状态形成识别，不需要装饰照片或插画。
- 窗口缩小时必须说明导航、列表与详情如何让位；不把三栏挤满两档窗口。
- 概念轮已结束，用户已从实际首屏中选 A；当前允许只深化 A 的独立交互原型，仍不修改正式产品包或其他方向。原型确认后再进入正式实现。

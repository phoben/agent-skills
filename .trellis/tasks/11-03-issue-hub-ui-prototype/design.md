# U1 原型设计流程

采用父任务 [UI 原型计划](../11-03-github-issue-plugin/ui-prototype-plan.md)；用户已接受页面内仓库导航。只保留一个宿主主入口。

三个方向已通过概念与灰度复核，用户现选择先看实际首屏。本轮制作 A/B/C 各一张固定 1120×880 插件画布，采用同一仓库、同一已选 Issue、同一内容与主动作；差异是其选中后的版式。B 展示独立阅读页，A 保留旁侧队列，C 原位展开。都是代表首屏，不制作整套交互流程。

最新阶段：三首屏已交付，用户已选择 A。上段保留对比轮次说明，当前只制作 `ui/prototype/a-v1/` 的完整交互原型。A 的 164px 仓库导航、316px 队列、详情余宽、墨绿选中提示和系统字体作为基线；内容区可伸缩，不保留固定 1120px 整页裁切。

## 当前实现边界

- `index.html`：语义外壳与页面入口；`styles.css`：选中 A 的 CSS 变量、主题、窗口变化和轻量动效。
- `app.mjs`：列表、详情、表单、菜单和焦点；可按职责增加少量本目录模块，避免大段内联脚本。
- `store.mjs`：独立演示数据、身份/仓库隔离、草稿和本机持久化、模拟读写及故障，不接真实服务。
- `fixture.json`：来自对比轮共享内容，补充多仓库、空仓库、只读等可核对的演示场景。
- 沿用现有 Issue Hub 的原生 DOM/ESM 技术，不给项目引入新框架、生产构建工具或远程 CDN；这是本仓库存量技术的延续。

默认首次进入为列表，用户点击 Issue 才打开详情；可用查询参数进入代表性演示状态，但保存和失败验证必须从实际操作开始，不能仅摆终态。1120×880 为主可用画布，960×680 为小画布；独立预览可铺满更宽窗口。小窗收起仓库到页面内抽屉，选中后队列 280px 与详情余宽；更窄时用单详情和返回。

原型沿用共用交互约束。新建、编辑、评论、标签/负责人/里程碑、关闭/重开通过本机 mock 数据完成；刷新可读回。失败保留输入，离线仅保存本机草稿，冲突需明确处理。任务按钮只模拟请求状态与提示词展示，不打开真实 Codex，也不伪造已持久化聊天。

QA 通过 URL 的 scenario/theme/run 参数选择模拟故障与隔离数据，不在产品画面增加调试工具条。至少覆盖 offline、save-error、conflict、read-only、account-change、loading、unavailable、ambiguous、invalid-workspace。故障应在实际触发相关操作时返回，不能跳过保存流程。

三处基本动效用于详情进入、菜单/弹层出现和提交反馈，尊重 prefers-reduced-motion；不使用装饰性动画。完成后先自查真实截图，再按技能做独立视觉评审和开放式 UX 走查，最终由用户确认原型。

页面采用同一份 fixture.json 作为唯一演示内容源，各自独立的静态生成脚本、HTML 骨架和 CSS；不共享页面模板换色。候选必须禁用 JavaScript 仍有完整内容。使用 oil-ui-pro 自带 build_explorer.py 生成中立对比页，不自写外壳；用 shoot.mjs 一次截齐三屏和总览，主 Agent 实际看图后修正明显重叠、裁切和粗糙。此轮不派画面打分评审，不做响应式或动效。

浅色统一用于本轮比较，正式选中原型再验证浅深主题和小窗口。首屏内没有“示例、未接入”等制作说明；数据和未实现范围在对比说明中明确。不会访问 GitHub 或创建真实聊天。

产品参考与交互参考分别取得真实证据；无法访问的参考标注缺口，不假装操作过。概念代理只拿事实包，不拿主 Agent 偏好或参考截图；独立评审不能由概念作者兼任。

选定后制作一套可交互页面及确定性数据，验证主要和异常状态、两档尺寸与浅深主题，取得实际画面及独立视觉/UX 评审，再请用户确认。正式代码按通过原型实现；未验证的宿主与 GitHub 联调继续单列。

# 0.2.1 前端体验改动与验证

2026-11-04。按用户对真实桌面页面的反馈，在已确认 A 布局上增加列宽调整，修复单击反馈阻塞，缩短列表和正文的前置等待。前端源码已冻结，独立检查与真实浏览器测量由 root 接续。

## 改动前反馈

开始改动前，实际执行了当时控制器中的 `openIssue` 和 `preserveBefore`，以未决请求分别卡住偏好写入、详情读取和会话恢复，结果保存在 [ui-delay-baseline-021.json](ui-delay-baseline-021.json)。这是可控请求的阻塞定位，不是 GitHub 网络耗时测量。

- 偏好写入尚未返回时，点击后的 `selected` 仍为 null，甚至尚未发出详情读取。
- 偏好和详情均返回、会话恢复仍未返回时，选中对象已经变化，但正文渲染次数仍为 0。
- 会话恢复完成后，正文才首次渲染。原事件已使用 click，用户感觉需要多次点击的原因是上述等待链。

首次首页还有重复 bootstrap、等待编辑候选后才撤去列表加载态的问题。本轮把这些等待移出了正文和选中反馈的临界路径。历史基线脚本用于记录改动前运行；当前代码的可复现回归在产品测试目录。

## 列宽与单击

- 新增独立 `ui/layout.mjs`：默认项目 164px、Issue 队列 316px；项目 164–420px，队列 280–640px，并保证详情至少 360px。窗口不足时先收紧实际宽度，不覆盖用户较宽窗口的偏好；原有抽屉和单详情规则继续生效。
- 两条分割线提供指针捕获、悬停/焦点反馈、左右键微调、Shift 加大步长、Home/End 边界、Enter 或双击恢复单列默认；导航底部可恢复全部默认列宽。取消拖动不保存。
- 拖动中只更新 CSS 列宽变量，不重绘表单、不发 MCP 或 GitHub 请求；结束后通过当前账号 SQLite `view-state-save` 保存偏好，不依赖可能不可用的 iframe localStorage。
- 新增 `ui/selection.mjs`。干净或已保存的输入下，单击立即切换选中与骨架；偏好后台保存，不再等它返回。未保存输入仍须可靠保存，失败保留表单并阻止离开。新选择优先，同一选中项不重复请求，旧失败或旧结果不再把页面跳回去。

## 分阶段读取与守卫

- 首页可以直接消费宿主已送到的 bootstrap，避免重复身份/目录请求；仓库选择与列宽都来自当前稳定账号的本机偏好。
- 列表 `cacheFirst` 先给可信缓存；正文 `read-summary` 只取正文与属性，先呈现可读详情，再读取评论、活动、候选和会话。未读取的讨论明确显示尚未完成，不写成没有评论。
- 缓存明确显示后台检查状态，严格读取随后更新；`cached/checking/networkChecked:false` 不算新的 GitHub 成功时间，也不能把已知离线状态标回在线。
- 同一在途只读请求合并；同版本摘要/列表保留已读讨论的分页投影。后台讨论更新只替换讨论区，会话更新只替换关系区，当前表单与输入不重建。
- 新增仓库访问代次、写入代次与任务代次守卫。明确失权后，在途旧摘要不能恢复私有数据；先前评论页不能覆盖写后读回；先前 latest 不能覆盖用户刚打开的新任务。账号切换仍清旧投影、请求与界面偏好。

## 验证结果

`node --test packages/issue-hub/test/product-ui-experience.test.mjs packages/issue-hub/test/product-ui-store.test.mjs`：40 项通过，其中新增体验测试 7 项。体验回归直接抽取并执行当前控制器函数，覆盖偏好或会话请求永久未决时仍能单击选中和显示正文、快速切换 latest wins、候选未决时列表先可用、草稿失败保护、分割线拖动/取消/键盘/窄窗边界。

Store 回归新增初始 bootstrap 零重复请求、账号内列宽/仓库记忆、缓存不伪造联网与成功时间、在途读取合并、摘要不请求完整讨论，以及三类后台旧结果不能覆盖新状态的场景。既有身份、分页、权限、草稿、未知写入恢复等回归仍通过。

`npm --prefix packages/issue-hub run check`：37 个 JavaScript 模块语法通过。此结果不是类型检查、真实桌面体验或 GitHub 性能改善的替代；首次真实 Issue/正文前后耗时及拖动后实际画面由 root 继续取证。

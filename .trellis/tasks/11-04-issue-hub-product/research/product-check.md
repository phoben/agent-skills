# Issue Hub 产品代码检查

2026-11-04，独立 trellis-check 审查。共享工作区，未回退其他实现者修改；未自动操作 Codex UI，未写真实 GitHub，未提交或推送。

## 已修复

- `src/services/issues.mjs`：仓库或资源明确返回 403/404 后撤销对应仓库读取缓存，保留草稿与回执。后续离线不能重新展示已明确失权的旧私有内容。
- 同文件：在 `/user` 成功后发生的资源 401 同样撤销凭据到稳定身份的离线映射，避免下一次断网绕回旧授权。
- 同文件：写入接受后独立核对实际字段；评论按真实 ID、父 Issue 和正文哈希读回，不因 Issue 列表可读取就误报评论保存确认。只读恢复复用这些检查，不重复发布。回归覆盖不一致读回与恢复。
- `ui/store.mjs`、`ui/app.mjs`：列表轮询不拥有评论/活动分页。保留已读讨论和当前选中对象；远端版本变化时标记详情旧投影并沿用 notice 提示输入保留、编辑后刷新。真实详情重读清掉标记；保存中不启动并发轮询。
- `ui/store.mjs`：在线缓存命中不等于断网。GitHub 的明确 offline 状态决定网络提示；任务恢复不提升 GitHub 联网状态、不刷新最后成功时间。
- `ui/ui.mjs`：结果未知的已有任务按钮显示“核对打开结果”，避免误导为新建。
- `ui/store.mjs`、`ui/app.mjs`：同名仓库失权或读取403/404时清除读取投影，立即隐藏旧详情与队列内容。未发布输入先保留在当前身份草稿，再走原串行保存队列落本机；迟到的较旧草稿成功或新草稿保存失败都不覆盖刚保留的输入。旧身份的迟到授权错误不清理新身份投影。
- `ui/ui.mjs`：未加载/不可访问数量使用“—”，部分加载保留“+”，完整空仓库才显示0，不把失败当空数据。
- `ui/store.mjs`：编辑草稿只包含可编辑输入及最小版本比较基线，不把整条评论与活动重复保存两份，避免长讨论触发512KB草稿上限。

以上均有行为回归；检查脚本只做 JavaScript 语法核对，不称为完整 lint 或 TypeScript 类型检查。

## 增量与未修复事项

- 审查发现目录仍按 remote 名称去重，改名旧 URL 与新 URL 指向同一 GitHub ID 会产生重复项。此项涉及规范键的公共契约，已先报告主会话，由目录与后端实现者增量处理。最终已定向复核：当前身份确认元信息后按稳定ID整轮归一、保留全部工作区与原始发现；改名不变规范key；另一账号未知/失权项保留诊断，不沿用旧账号规范元信息。对应目录与服务回归通过。
- GitHub 保存前比较和提交之间仍有非原子竞争窗口；当前代码不能声称 GitHub CAS。此为平台约束，保持在交付与规范里。
- 已确认的编辑请求按同 operationId 重放时，保存前基线比较可能先返回 CONFLICT，而不是直接返回旧 confirmed 回执；不会重复写入。未知和读回失败已有明确恢复入口。本轮未重排公共写入/回执校验顺序，此行为已向主会话报告，若需改善重放体验应按明确增量处理。
- 真实 Codex 新草稿工作区、已有未发送草稿保护、发送后真实关联及第二台 Windows 安装，仍须实际验收；自动化和包外资源读取不能替代。
- 主会话已同步 backend/frontend spec 的正式 APP_URI、固定工具、SQLite/expectedIdentity、稳定仓库 ID、离线凭据和回执恢复契约；P0历史验证边界保留。纯本机草稿/偏好/本机状态已由实现者改用当前scope已验证别名及已发现键，不依赖失权后的在线仓库权限，也不返回旧读取缓存。

# Issue Hub 方向卡

日期：2026-11-03。阶段：方向探索。概念由无会话历史的独立代理基于 [产品事实包](../../11-03-issue-hub-ui-prototype/research/product-facts.md) 产出，主 Agent 整理为三份候选；没有预先给作者推荐风格或标杆截图。本文只有文字和灰度结构，尚未渲染原型，不能声称视觉或交互验收。真实参考与限制见 [参考记录](references.md)。

本轮截图采集超时，参考只依据真实网页 DOM、导航操作和官方说明；没有看图的部分明确标为未验证。以下字体、色板、主视觉均为待实际渲染验证的设计提案，不是对标杆外观的复述。独立评审只审概念、结构、成本和差异，不作实际画面评分。

## 共用边界与灰度标尺

核心对象是 Issue，依靠编号、标题和状态识别；关联聊天的真实性、当前数据时间及未发布输入不能藏起来。主动词是查看、读讨论、进入聊天处理。频率为每天反复使用，因此三个候选都以列表起步，保留密集扫描能力，不放指标卡、欢迎区或海报。

调性共用：安静、边缘精确、密度偏高、字重偏轻、表达严肃。依据是 Windows 桌面端的高频跨仓库处理。明暗变化只承担对象、选中和反馈层级；强调色在正常画面中控制在约 6% 以内。主动作允许填色，辅助动作使用文字或细描边。

宿主真正分配的插件画布尺寸未知。灰度采用保守占位：1440×1000 宿主中只使用 **1120×880**，为原生导航和边框预留合计 320px 横向、120px 纵向；1280×800 宿主只使用 **960×680**。这只是概念预算，不能视为已测得宿主尺寸。后续应以实际桥接画布尺寸验证，布局断点按插件画布宽度判断。

图例：`░` 为外壳，`▒` 为选中对象，`█` 为唯一主动作或当前焦点；空白为内容区。示例编号、文字、关联状态均为确定性演示内容，不代表真实仓库数据。灰度中的横线不代表装饰性粗边框。

### 不因方向改变的状态与操作

| 情况 | 必须发生的可见结果 |
| --- | --- |
| 打开、前台每 60 秒检查 | 数据区保留，展示检查中；最后成功时间保持原值，成功后才更新 |
| 写后读回 | 保存中保留输入；远端读回成功才显示已保存，读回失败明确显示结果尚未确认 |
| 仓库无 Issue / 筛选为空 | 前者写“此仓库暂无 Issue”，后者保留筛选并给“清除筛选”；不共用一句“暂无数据” |
| 评论分页未完成 | 展示“已加载 20 / 57 条评论”和“加载更多”；完整正文、活动、附件链接与关联 PR 可继续阅读，不截成摘要替代详情 |
| 断网、缓存 | 显示“离线缓存 · 最后成功时间”；仍可阅读缓存和保存本机正文／评论草稿，恢复后由用户手动提交 |
| 权限不足、账号变化、限流、失败 | 各有原因文字与对应恢复入口。账号变化立即清除旧账号私有视图和在途响应；本地缓存、草稿与聊天关联按身份隔离，新账号页面不得继续展示旧账号缓存。清除当前视图不删除按旧身份保存的草稿，旧响应也不得回填新视图。未知计数用“未获取”，不补零 |
| 远端冲突 | 保留本机输入，显示远端版本与本机草稿的比较入口；用户决定采用哪份，不自动覆盖 |
| 无确认关联且工作区有效 | 主入口“创建任务”；单一有效工作区或有效已记路径，一次点击即准备并打开预填草稿，不拆为准备、打开两步 |
| 未发送草稿 | 明确写“未发送草稿”，只表示本机准备内容；不画成已关联聊天 |
| 已发送请求但关联未确认 | 写“请求已发送 · 关联待确认”，进入关联状态说明；不启用一个冒充已确认的“返回会话”链接 |
| 首次多路径 / 已记路径失效 | 首次多路径选择本地工作区并“确认绑定”，记住后复用；已记路径失效时重新选择。单一有效工作区和有效已记选择不增加确认步骤 |

新聊天只能预填，成员在宿主发送后才开始分析、实施和验证。宿主对未发送草稿能否再次定位、发送请求能否追踪及关联确认事件的具体能力未知；原型应分开演示三种状态，能力确认前不承诺自动回跳或实时进度。

新增和编辑进入内容编辑状态，唯一主动作变为“保存”；评论输入获得焦点后唯一主动作变为“发表评论”。标题正文编辑、关闭／重开、本人评论编辑、已有标签增删、负责人和里程碑调整都必须可达。仓库标签定义及删除入口指向 GitHub，不在插件中扩张管理范围。此阶段不会访问或改写真实 GitHub，也不会打开、创建或发送真实聊天。

## 方向 A：连读队列

**一句概念：仓库固定在左，Issue 队列维持位置，选中后在旁边连续读完并进入处理聊天。**

生成引擎是“逐条处理的队列”。事实依据是每天反复切仓库和处理多条 Issue。北极星是读完当前条后，用户仍知道自己在仓库列表的什么位置。

### 导航、主角与动作

页面内常驻 164px 仓库导航，仅显示已发现的仓库及当前选择；同仓库多 clone 不重复成多条仓库。仓库很多时导航内部滚动、顶端搜索。Issue Hub 名称只在导航顶部一处出现。选仓库保留其本机筛选与阅读位置，是否跨会话保留阅读位置属于设计建议，产品要求尚未明确。

初始主角是 Issue 队列，唯一主动作是打开一条；工具条的新增、筛选、刷新均为次级。选中后主角是正文与讨论，详情标题下紧邻一个“返回会话”或“创建任务”主按钮；其他管理收在“更多”和可编辑属性中。

流程：点击仓库 → 扫描列表 → 点击行 → 队列收窄并保留选中行 → 右侧阅读正文、分页评论和活动 → 点击任务主入口 → 有确认关联则“返回会话”；缺关联且工作区有效则点击“创建任务”一次即准备并打开预填草稿，仅首次多路径需确认绑定，已记路径失效时重新选择。关闭详情恢复全宽列表与原滚动位置。按上下方向键移动焦点，Enter 打开；不会在关闭 Issue 后擅自自动选下一条。

### 对象、字体、色彩与控件

对象行是两行文字，52px 高：左侧 14px 状态图标与编号，第一行标题最多一行；第二行依次为最多两个标签、负责人、更新时间。截断只用于列表，聚焦或详情显示完整标题。选中以 3px 左边条、选中底色和文字权重表示，键盘焦点另加 2px 外框。未分配写“未分配”，未知更新时间写“未获取”。无头像依赖。

字体：`Segoe UI Variable Text, Segoe UI, Microsoft YaHei UI, sans-serif`；中文由系统回退。标题行 14px/600，详情标题 18px/600，正文 14px/400、22px 行高；元信息 12px/400，仅作辅助；编号和时间用 Segoe UI 等宽数字。16px 是主要控件文字上限，无展示大字。

色彩来自长期阅读与当前位置定位需求，选择墨绿强调，视觉识别集中在队列边条，品牌主色尚未给出。

| 用途 | 浅色 | 深色 |
| --- | --- | --- |
| 外壳 / 主区 | `#EEF2F0` / `#FFFFFF` | `#151C19` / `#1B2420` |
| 主文本 / 次文本 | `#1D2C25` / `#5C6D64` | `#E1EAE5` / `#A7B8AE` |
| 主强调 / 选中底 | `#236248` / `#E5F0E9` | `#8CC8A4` / `#263D30` |

主视觉就是窄队列里的状态、标题、更新时间对齐；不增加插画。使用自包含 16px SVG、1.5px 描边、圆端点；Issue 状态为开口圆／带勾圆，聊天为方角气泡，文字始终说明真实状态。按钮 4px 圆角，28–30px 高；选中条直角，标签浅底细边不使用成排实心彩块。展开约 140ms 横向分区变化，支持减少动效。

**记忆点：** 同一条选中边线从宽列表保持到窄队列，右侧正文与该行对齐；来回处理时阅读位置稳定。识别来自持续选中关系，不增加第二个状态仪表。

### 状态落点、1280 降级、成本

共用状态表全部适用。底部状态条显示刷新时间、离线、账号与限流；账号变化立即清空旧账号的队列、详情及在途响应，按新身份读取隔离的缓存和草稿；错误的具体恢复动作放在相关内容区域，避免一条状态栏承担全部说明。无数据和筛选为空发生在队列；首次加载用行骨架，不伪造统计。评论分页提示随讨论末尾；草稿标记贴编辑器，冲突比较替换编辑器旁的说明区且保留输入。

1280 宿主采用 960×680 画布：仓库常驻导航收成工具条的“仓库”按钮，打开原垂直列表抽屉；未选中时列表全宽，约 11 条完整行。选中后为 280px 队列＋680px 详情两段，移除第三段常驻导航；详情正文可继续完整阅读。画布低于 900px 时进一步改为单详情页，返回保留队列位置，此断点仍需实际宿主验证。

资产：约 12 个可复用 SVG 微图标，无图片、远程字体、付费服务。技术成本中等：维护主从选择、双滚动区与导航抽屉；本机偏好、草稿和关联由既有桥接承载，桥接具体能力待核对。没有拖拽、实时协同或动画库依赖。代价是展开后队列标题可见长度下降，需要详情承接完整标题。

## 方向 B：比较表与专注阅读页

**一句概念：列表阶段把宽度交给比较，打开 Issue 后把整张画布交给正文与讨论。**

生成引擎是“打破列表旁常驻详情的惯例”：比较和阅读在两个明确视图中完成。事实依据是需要跨 Issue 判断状态、负责人和更新时间，同时完整阅读长正文与分页评论。北极星是每一步只占用一种阅读尺度。

### 导航、主角与动作

页面顶部左侧用 240px 仓库选择器，点击打开带本机项目搜索的仓库选择面板；不设常驻侧栏，也不把仓库展成无限页签。菜单中同仓库只出现一次，本地路径随“创建任务”处理；单一有效工作区直接打开预填草稿，首次多路径才确认绑定。

列表主角是可比较的 Issue 行，唯一主动作打开一条；筛选紧邻列头，不放总量指标卡。详情主角是完整 Issue，唯一主动作在标题区“返回会话／创建任务”。返回列表带回筛选和滚动。编辑、关闭／重开等进入标题旁的次级“更多”，属性行保持可达。

流程：选择器切仓库 → 在表格按列扫描 → 点击标题或 Enter → 页面切换为阅读视图 → 阅读正文和全部分页讨论 → 点击“返回会话”，或点击“创建任务”一次准备并打开预填草稿（单一有效工作区或有效已记选择不加确认，首次多路径确认绑定）→ 返回列表恢复原行。上一条／下一条是详情内的次级导航，不发生 Issue 状态变化。面包屑只显示“返回列表”和编号，不重复整串仓库名。

### 对象、字体、色彩与控件

对象是 36px 单行表格，标题列占约 53%，编号与标题同列但编号降低对比；负责人、标签和更新严格列对齐。悬停背景轻微变化，聚焦为 2px 内框。选择整行进入详情前仅做一次背景确认，不制造多选复选框和未授权批量操作。长标题列表截断，详情完整显示。状态文字在聚焦时可读，不能仅靠圆或颜色判断。

字体：`DengXian, Microsoft YaHei, sans-serif` 用于标题与行文字，采用 Windows 系统字族；编号、时间采用 `Consolas, monospace`，兼顾中英文混排。表格标题 15px/400，列头 12px/600，正文 15px/400、24px 行高，详情标题 22px/600。相较 A，标题更舒展，数值的窄等宽对齐成为主要性格。字体在系统不存在时回退，不要求安装字体。

色彩选择中性石灰底加铁锈红强调，把表格线和打开动作分开。来源是比较阅读需要低色噪、切页时需要明确落点；没有把错误红借作全局状态色。危险动作仍附明确文字和独立确认，不单靠同一色相区分。

主视觉是整幅横向对齐的文字表格与打开后的长阅读页，无卡片阴影。14px SVG，1.25px 描边、平端点；少用图标，表头和属性以文字优先。按钮 2px 圆角、30px 高，输入用完整矩形边框；标签为文字加 3px 小方点，选中以整行底色和表格焦点框表达。页面切换为 100ms 透明度过渡，不做翻页仿真。

### 状态落点、1280 降级、成本

共用状态表全部适用。同步与账号在底部，读回失败在页头下单行提示。无 Issue／筛选为空替换表体并保留列头和筛选。权限不足、限流在对应列表或详情上方说明，不将列值置零。账号变化立即清除旧账号表体、详情和在途响应，按新身份加载隔离的缓存和草稿，不保留旧账号私有画面。编辑和评论可在专注页中切为整宽内容编辑态；冲突以“本机草稿／远端版本”比较视图展示。未加载评论数量在讨论标题与末尾可见，草稿状态贴近输入框。

1280 宿主采用 960×680：列表保留状态、编号标题、负责人、更新时间；标签并入标题悬停／聚焦的补充行或详情属性，不采用横向滚动当常态。可见约 15 行。详情取消右属性轨，属性和页内锚点折成标题下的一行弹出入口，正文占满宽度，建议最大正文行宽 760px；评论编辑器保留完整宽度。不会出现列表与窄详情互相抢位。

资产：约 9 个自包含 SVG，无外部素材。技术成本低至中：列表和详情路由状态、返回时恢复滚动、可选的上／下一条。无需双列联动、拖拽或动画依赖。代价是快速跨条对照需要返回列表或用上／下一条，持续处理的空间位置感弱于 A；它以完整阅读宽度换取这项差异。

## 方向 C：Issue 与聊天的对照行

**一句概念：每个 Issue 在列表里同时展示一条本机关联状态，点开后沿同一行展开讨论，处理入口跟着这个对象出现。**

生成引擎直接来自产品特有关系：**远端 Issue 与本机 Codex 聊天是两个对象，准备、发送、确认关联又是三个不同阶段。** 用两段端点与实／虚线表达关系，但始终由 Issue 列表组织页面，不做会话看板或双对象卡片墙。北极星是用户在发起处理前，先辨清“有没有已经处理它的聊天”。

### 导航、主角与动作

顶部是一行页面内仓库页签，显示当前仓库与最多三个邻近仓库，其余收入“全部仓库”搜索菜单。只表现导航，不附仓库统计卡。页签数量与顺序是本机偏好，不把固定三个仓库当产品事实。长仓库名限制在 220px 并支持悬停／聚焦完整名称。

未展开主角是 Issue 列表，唯一主动作打开一条。关联列仅为文本状态，默认不放逐行任务按钮。展开后该 Issue 正文和讨论是主角，在它的行内标题下出现唯一任务主入口；其他属性和管理收于同一行的文字入口和更多菜单。

流程：切仓库页签 → 扫描 Issue 标题及本机关联状态 → 点击 Issue 行 → 正文和讨论在原行下展开，其他对象仍为列表 → 点击展开区任务主入口 → 有确认关联则“返回会话”；无关联且工作区有效时，“创建任务”一次点击即准备并打开预填草稿，仅首次多路径确认绑定，失效路径重新选择 → 本机关系阶段有真实证据后才更新。一次只展开一条，点击另一条时前一条收起；保存中的内容或草稿不会因收起丢失。收起回到原列表位置。

### 状态落点、1280 降级、成本

## 三方向共用的操作细则

### 已有会话与另建任务

确认关联时主按钮为“返回会话”；旁边独立的展开按钮有“会话操作”可访问名称。点击或键盘展开后，菜单明确包含“另建任务”，不是仅画一个 v。

选择“另建任务”会保留原关联及历史，使用当前有效工作区准备新的独立引用，并直接打开预填新草稿，不发送。首次多路径或绑定失效才出现工作区选择；取消后不创建请求、不改变关联。新请求待确认期间旧关联仍在历史中，不把新草稿画成替换了旧聊天。缺少确认关联时主按钮“创建任务”一次点击准备并打开；索引延迟或多匹配只显示待确认或歧义。

以上是产品交互约束，原型以确定性状态演示，不会真实打开或发送聊天。

# Issue Hub 设计说明

日期：2026-11-03。用户已选择 A 连读队列，当前制作其完整交互原型。业务需求见父 PRD，事实及删除清单见 [产品事实包](../../11-03-issue-hub-ui-prototype/research/product-facts.md)。

## 设计北极星

看清当前 Issue，在清楚的仓库与工作区上下文中进入正确会话处理它；每一步都能判断数据是否最新、输入是否发布、聊天是否真实关联。

## 已确定边界

- 一个 Codex 主入口，进入页面后切换仓库；本轮用户已同意这种交互，不再等待原生浮层契约。
- 适用于 Windows 高频开发工作区，中文操作文案、宿主浅深主题、自包含前端与系统字体。
- 列表先行，保留正文、全部分页讨论和日常管理；不添加总览指标卡、欢迎海报或无业务作用装饰。
- 列表主动作打开 Issue，详情主动作创建任务/返回会话；编辑和评论模式分别以保存、发表评论为主动作。
- 单有效工作区一键准备并打开未发送草稿；“另建任务”独立保留历史。账号变化清旧私有视图，未发布输入保留本机草稿。
- U1 只操作确定性演示状态，不写 GitHub、不创建真实聊天；未完成的项目覆盖与会话联调仍留在后续验收中。

## 方向与当前建议

三份 [方向卡及灰度结构](direction-cards.md) 已经独立概念生成和另一位评审者复核，见 [评审记录](reviews/direction-review.md)。修订已补另建菜单、键盘/焦点、编辑保护及小窗口灰度，并统一 A 窄窗为 280/680。

- A 连读队列：仓库常驻，选中后队列与详情相邻；小窗口让仓库让位到触发器。
- B 比较表与专注阅读页：仓库在顶部选择，列表全宽扫描，详情单独占阅读页。
- C Issue 与聊天对照行：仓库页签，列表显示本机关联证据，选中后在原行展开正文。

用户已明确采纳 A 作为实现基线：多个仓库和多条 Issue 连续处理时，仓库入口与阅读位置稳定，返回列表的次数较少。代价是选中后列表较窄；小窗口采用两段及仓库抽屉，不强挤三栏。完整原型确认仍独立进行。

## 证据与下一步

[参考记录](references.md) 区分了实际 DOM/导航、官方说明和未取得的截图。GitHub 列表到详情实际走过，Linear Display options 实际读取；截图接口超时，所有字体、色彩与主视觉仍待实际渲染验证，本轮不提供视觉评分。

用户可从文字选定一个方向，之后只制作该方向的完整交互原型；若先看画面对比，则按技能仅制作三张同数据首屏，再选择。原型完成后仍需实际截图、独立视觉与 UX 走查，并记录用户确认，才能开始正式界面。

## 共用修订

1. **明确已有会话后的另建入口。** 事实包要求优先“返回会话”，同时保留另建。三张灰度都画了 `v`，但未说明其内容。补为明确的次级菜单入口，例如“另建任务”，并写明：使用同样的工作区选择规则、只打开预填草稿、不会覆盖现有确认关联或把新草稿记成已关联。已有主按钮仍为“返回会话”。不需要增加第二个同权重主按钮。
2. **补一份三方向共用的键盘与输入约定，再列各自差异。** 至少交代 Tab／Shift+Tab 可达仓库切换、列表、任务入口、更多、分页和编辑器；选择面板怎样确认和关闭；退出详情或收起后焦点回到哪里。正文／评论输入时保留正常换行，列表方向键和 Enter 不截获输入，不因收起、返回或切换丢失草稿；Esc 不直接丢弃或提交内容。A/B 已写的键位不足以覆盖这些路径，C 尚未写键位。
3. **把两档输入场景落到灰度。** 目前两档宽高预算与窄窗让位说明足够具体，可以继续画；但第二档只有文字，且 A 的导航、B 的属性轨都发生结构变化。补 960×680 的简短线框，并标出编辑／评论输入和保存／发表反馈位置，尤其是出现错误或冲突后仍有输入空间。无需增加第三档或制作完整 HTML 原型。

## 已满足的边界与后续约束

- 三者都沿用唯一插件入口及页面内仓库导航，以 Issue 列表起步；主角和主动作随列表、详情、编辑、评论状态改变，管理操作有次级入口。
- 完整正文、分页评论、活动、附件链接与关联 PR 均有去向，列表截断不代替详情。A 双滚动、B 返回定位、C 长展开的可用性仍需真实原型验证。
- 共用表明确单一有效工作区一次点击创建草稿、首次多路径确认、失效路径重选；未发送、已发请求待确认、真实关联分开。桥接能力未知已如实标明，未承诺自动发送或自动回跳。
- 账号切换明确清除旧私有视图和在途响应，缓存、草稿、关联按身份隔离。断网、权限、限流、未获取、空仓库和空筛选有区分；失败保留输入，写后读回才确认保存。
- C 目前没有增加优先级、执行阶段或任务流水线，实／虚端点只是事实映射。实施时不把“阶段序号”扩成分析／实施／验证进度，不凭点击或时间推断“请求已发送”及“确认关联”；未知仍显示未获取。
- 素材均为本地系统字体和少量自包含 SVG，没有远程字体、付费资产或新增图布局库。成本差别已写清，C 的滚动锚定最复杂但无不可获得资产依赖。真实桥接契约仍是实施前核对项，演示状态不能充当真实集成验收。

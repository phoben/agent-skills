## 整体判断与三秒测试

把默认列表与遮字图分别缩至 480px 宽观察后，两句话判断如下：

- 它像 2020 年代的桌面开发工具 Issue 工作区，采用熟悉的仓库导航和紧凑队列。
- 第一眼看到的是左侧当前仓库与右侧连续的 Issue 队列；进入详情后，主角明确变为右侧当前 Issue 的标题与返回会话动作。

骨架属于适合高频处理的品类基线。遮字后仍能看出导航、筛选、对象队列与当前项的层次，没有指标卡、装饰插图或多层卡片把业务阅读切碎。这个判断不要求工具为了新奇改掉成熟导航模式。

同类优秀工作区通常把当前对象、阅读内容与下一步动作放在近处，同时把导航和属性降到次要层级。这里的选中详情基本做到这一点：1120×880 下，仓库栏约 164px，队列约 315px，详情约 641px。默认列表首条标题在 y≈184，首屏完整容纳 12 条对象，并露出下一条；没有用疏松卡片牺牲扫描密度。详情主标题下方紧接“返回会话”，动作离对象很近，正文则从 y≈230 开始。正文、复现步骤、验收条件和讨论提供了问题的前因后果，没有把详情做成第二张属性表。

本轮未联网获取对标产品图，因此这里只比较工作区的任务组织与可见完成度，不声称做过同屏对标。

## 提升

### 1. 设计感与业务重心：把关联状态写得更具体

位置：1120×880 详情顶部，以及 960×680 深色详情顶部。

观察：墨绿“返回会话”是清楚的主动作，旁边却只有“已确认关联”。用户能判断关联有效，不能从这处信息判断会进入哪一段会话。对于需要在明确仓库、工作区中进入正确会话的工具，这块位置最值得继续做细。

影响：当前 Issue 的身份很明确，会话的身份仍较抽象。用户要靠记忆或先跳转才能再次确认目的地。

验收目标：在原有状态区域内，让关联确认与目的地同时可辨认；用具体会话信息替换一部分泛化状态文字，不新增卡片，不把主按钮挤到下一行。用当前详情截图在 100% 下检查，首次看到页面的人能说清“正在看哪个 Issue”和“按下按钮会回到哪段会话”。

这属于中等提升。当前证据没有证明关联错误，不能据此认定会跳错或把分数压入阻断档。

### 2. 精致度：消除窄画布的重复仓库抬头

位置：960×680 深色截图顶部。

观察：顶栏“仓库”按钮旁显示 `team/issue-hub`，下面队列工具栏又显示同一个 `team/issue-hub`。两行相距很近，字重也相近。它们都在强调同一上下文，窄画布因此多付出一行高度。

影响：标题和正文仍可读，但工具栏的重复感比宽屏明显，讨论区在 680px 高画布中只露出标题条。长讨论采用独立滚动是合理的，这条建议不要求把讨论或输入强塞首屏。

验收目标：减少其中一处重复仓库文字，保留清楚的当前仓库和导航入口；复查深色窄画布，空出的高度确实回到队列或阅读空间，主动作位置与正文起点仍稳定。

200% 列表图中的图标、输入框描边和标题基线没有明显粗糙处。100% 下中文没有明显孤字或断行错误。导航文字、队列内容和详情正文各自有稳定锚线；详情标题、正文、小标题与讨论区共享左边缘，没有观察到需要逐项补齐的散乱缩进。

### 3. 动效：本轮不判断完成度

已提供 `record-entry.mp4` 与 `record-打开详情.mp4`。当前查看工具不能正常速度播放视频，本轮没有打开共享浏览器，也没有用抽帧推断动效通过。

报告中的位移和透明度数值只能说明实现过变化。对这类专业工具，小幅运动可以成立，不需要为了“看起来做过动效”放大入场。后续验证的目标是：点击对象后，选中项与详情像翻到同一份文件的下一页一样接上；首次进入时能感到内容就位，输入又不需要等动画结束。没有正常观看前，不判断它现在是否达到这个手感。

## Lint 原文与判断

读取了 `primary-v2/report.json`、`detail-v3/report.json`、`failure-v2/report.json` 与 `dark-narrow/report.json`，没有跳过提示：

- `primary-v2`：静态 `issues: []`、`lint: []`；动效探测提示“首次进入：动画幅度太小，看不出来（最大位移 3px，尺寸变化 0.0%，透明度变化 0.12）”。不以该数值提示直接扣分；观看限制见上文。
- `detail-v3`：`headingSpacing` 提示标题“上 9px，下 14px”；`sideStripe` 指向选中 Issue。当前标题与编号、主动作形成完整头部，正文另起区块，未见错误归组。队列选中边线承担当前位置提示，属于有效状态表达。
- `failure-v2`：`sideStripe` 指向选中 Issue，以及“保存失败，输入已保留。请重试。”错误框。错误框使用淡红背景、红色文字和边线，阻断焦点明确，没有作为普通卡片装饰。
- `dark-narrow`：同样是上述 `headingSpacing` 与选中项 `sideStripe`。静态画面未见由此造成的阅读问题。

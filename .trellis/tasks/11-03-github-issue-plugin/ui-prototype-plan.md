# Issue Hub UI 原型计划

状态：2026-11-03 用户已选择页面内仓库导航，并从三首屏中明确选 A 连读队列；当前制作 A 完整交互原型，最终原型仍需用户确认。

## 目标与已知约束

让成员在 Codex 中连续完成“选择仓库 → 找到 Issue → 看清讨论并管理 → 返回或新建聊天”，无需为了日常操作反复切换 GitHub。

- 面向每天处理项目的 Windows 开发团队，中文描述与操作文案，插件产品名为 Issue Hub。
- Codex 保留单个插件主入口；用户已接受打开插件页面后切换仓库。页面内导航不冒充宿主原生浮层，也不新增多个主导航图标。
- 核心对象是 Issue 列表行、正文与讨论、编辑内容及关联聊天；不增加与需求无关的指标大屏、营销介绍或装饰主视觉。
- 沿用宿主主题与必要交互习惯。主视口按 1440×1000 验证，另验 1280×800；这些是宿主窗口尺寸，页面可用宽度需扣除实际原生侧栏和边框。
- gh 身份、权限、60 秒前台检查、离线草稿和本地会话关联均使用已确认的业务行为，不在视觉探索中改变产品范围。
- P0 已提供单入口和协议基础，U1 使用已确认的页面内导航探索；完整项目覆盖和真实会话验收保留到相应集成阶段，不在模拟原型中宣称通过。首版不设计移动端或 macOS 流程。

## 流程与停止点

使用用户指定的 oil-ui-pro。技能安装位置为 `C:/Users/NINGMEI/.codex/skills/oil-ui-pro/SKILL.md`，本次读取版本为 0.26.0；执行时按适用规则加载所需参考。

1. **准备产品事实。** 读取本任务 PRD、宿主结果及现有主题规范，分别记录产品参考和交互参考。参考取实际画面，不用记忆冒充调研。列删除清单，为列表、详情和编辑等关键状态明确一个主角和主动作，以及素材、设备与交互成本约束。
2. **探索并选择方向。** 按技能让全新概念代理基于事实包提出至少三个可落地方向，主 Agent 整理方向卡和主视口灰度结构，再由另一位独立评审者把关；通过后先向用户用文字说明方向和推荐理由。本轮结束等选择，不提前实现三套完整页面。用户希望看画面时才制作三张同内容首屏对比，选定后只深化选中方向。
3. **制作可交互原型。** 先做代表性的列表到详情与任务入口流程，再补齐编辑、评论和关键状态。数据使用确定性的测试内容，不访问或写入真实 GitHub，也不因点击演示按钮自动创建真实聊天。
4. **取得实际证据并评审。** 在目标尺寸运行，主 Agent 查看截图与操作结果；完成独立视觉评审、问题修正，再安排新的 UX 评审者从页面自主走查核心任务。按技能保留评审与复核记录，视觉和任务可用性分开验收。
5. **用户确认原型。** 交付可打开的原型入口、截图和关键流程说明，记录用户认可的版本与反馈。未明确确认时停在 U1，不进入正式界面实现；不因超时或默认选项推定批准。

需要几轮修改由实际问题决定，不预写“已通过”。已确认后如变更核心布局、主要操作或信息层级，先更新原型并再次确认；普通实现细节不重复发起决策。

## 原型覆盖

| 区域或流程 | 必须可观察的行为与状态 |
| --- | --- |
| Issue 列表 | 搜索和筛选、选中及返回位置、长标题、标签和负责人；加载中、空仓库、筛选无结果、错误和重试。 |
| 详情与讨论 | 正文、属性、关联 PR 和附件链接、评论与活动的切换或连续阅读；长文本、分页加载和部分覆盖。具体布局由方向选择确定。 |
| 新增及编辑 | 标题正文、已有标签、负责人和里程碑；保存中、成功反馈、失败保留输入、远端冲突及本地草稿。 |
| 评论 | 新增评论、编辑本人评论、权限不足和失败恢复；输入不因详情刷新被覆盖。 |
| 同步与离线 | 最后成功时间、手动刷新、前台检查、断网和限流；已有缓存与未知数据区分，恢复后不自动发布。 |
| Issue 会话 | 返回已有、另建、单路径与多路径首次选择；绑定失效、请求发出、等待发送、待关联、已关联、歧义与失败。 |
| 离开与恢复 | 切换 Issue 时未发布输入的保留或提示、弹层关闭后的焦点、返回列表的位置与筛选。 |

原型中的模拟数据、非真实写入及未接入宿主在交付说明中明确，不用制作说明占据产品界面，不宣称已成功写入 GitHub 或创建真实聊天。

## 验收与交接

- 方向与原型都有明确用户回复；未确认项不能写成已确认规范。
- 所选方向在两档桌面尺寸、浅深主题中可用；中文长标题及评论无重叠、裁切，键盘焦点与主要操作可达。
- 主 Agent 实际看过画面并跑过代表性交互，独立视觉评审与 UX 走查的问题有处理结论；缺少任何能力如实记录，不能用自检冒充独立评审。
- 会改变布局的加载、失败、草稿、冲突和待关联状态可展示，不只交付漂亮的默认页。
- 用户批准的版本作为后续实现基线，P2 及 P4 按它落地，最终仍须验证真实宿主和 GitHub 全链路。

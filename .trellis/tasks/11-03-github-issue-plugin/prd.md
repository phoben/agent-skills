# 设计团队 Issue 管理 MCP 插件

## 目标与状态

让团队成员在 Codex 桌面端直接选择本机项目对应的 GitHub 仓库，查看和管理 Issue，并将 Issue 带入正确工作区的新聊天。

2026-11-03 用户已授权设计完成后直接进入 Trellis 实施，不再重复请求整份方案开工确认。父任务保存总体需求，由 P0 等子任务承接实施；UI 方向和原型仍需用户确认后才进入正式界面开发。不包含提交、推送或正式发布。

## 背景与事实边界

- Tokens 已有原生 global 入口、stdio 服务与自包含页面实践，其历史线程分组不能等同完整桌面项目。
- 当前本机项目接口已有只读结果，多个仓库入口与工作区深链具备源码基础；端到端验收尚未通过。证据集中在 [宿主能力调查](research/host-capabilities.md)。
- 四轮产品选择已收敛；正式支持的最低 Codex 版本由第一阶段能力验证结果限定，不提前承诺所有版本兼容。
- 2026-11-03 已纳入 UI 原型要求，随后收到直接进入实施的授权；原型确认继续作为独立界面门槛。

## 需求

| 编号 | 使用场景与结果 |
| --- | --- |
| R1 | Issue Hub 在 Codex 主导航只有一个插件图标。用户已选择先采用插件页面内导航：打开页面后切换仓库，一仓库一项，主区域展示该仓库 Issue。首版不承诺宿主原生悬浮仓库栏，不产生按仓库拆分的多个主图标。 |
| R2 | 自动读取桌面项目工作区并识别 GitHub 仓库，保留仓库与本地工作区之间的对应关系；不以历史会话项目集冒充完整桌面项目集。 |
| R3 | 以列表展示所选仓库 Issue，点击查看详情，返回时保留浏览位置。 |
| R4 | 新增 Issue、编辑标题和正文、关闭和重开、新增及编辑自己的评论、已有标签增删、负责人和里程碑调整，写入 GitHub。仓库标签定义与删除操作不在首版范围。 |
| R5 | 完整查看正文、基本属性、全部分页评论、活动记录、附件链接与关联 PR；权限或数据不足明确说明。Projects、子 Issue 和依赖关系逐项标明支持情况并保留 GitHub 入口。 |
| R6 | 优先回到已有可靠关联聊天，保留另建入口。新建时选择正确工作区，预填可编辑开发任务提示词但不发送；提示词要求读取最新 Issue 与评论、遵循项目规范、分析实施并验证，提交推送及 GitHub 状态修改须另获授权。多工作区首次选择并记住，可修改；失效重新选择。关联不能靠标题或时间猜测。 |
| R7 | Windows 首发，从现有插件源安装独立插件。成员预装 Node 24、Git、gh、Codex，使用各自 gh 身份，缺失依赖明确提示；支持 github.com 公开、私有和组织仓库。协作经 GitHub，偏好及聊天关联留在本机，认证、缓存、草稿和回执不跨账号。 |
| R8 | 打开页面立即刷新，当前仓库前台每 60 秒检查，写入后立即读回，支持手动刷新；断网或限流显示延迟，不宣称实时推送。 |
| R9 | 离线查看已缓存内容、保存正文或评论草稿；恢复后由成员主动提交，不自动发布。 |
| R10 | 正式界面开发前使用 oil-ui-pro 完成 UI 方向选择和可交互原型，覆盖核心流程及关键状态，取得实际截图与独立评审后交用户确认。实施获批不等于原型获确认。 |

## 验收标准

- [x] A1（R1）：主导航仅一个 Issue Hub 图标；打开插件页面后至少两个仓库可在页面内切换，主区域数据、筛选和详情不串仓库；记录版本及画面。页面内导航不称作宿主原生浮层。
- [x] A2（R2）：已添加但没有聊天历史的桌面项目也能自动出现；桌面项目增删可同步；多路径、重复仓库及失效目录行为明确。
- [x] A3（R3）：真实非空仓库可浏览列表、进入详情并返回；PR 不混入 Issue 列表。
- [x] A4（R4、R8）：授权测试仓库完成新增、标题正文、关闭重开、评论新增及本人评论编辑、已有标签增删、负责人和里程碑调整；写后读回一致；正常网络且未限流时远端变更在下次前台 60 秒检查中被发现。
- [x] A5（R5）：超过 100 条评论的分页场景可读全；正文、活动、附件链接和关联 PR 的缺失状态明确。分页自动化与真实数据验收分别记录。
- [x] A6（R6）：真实桌面新聊天位于预期工作区，提示词正确且尚未发送；生成链接或独立 App Server 创建线程不能代替该项。
- [ ] A7（R7）：另一台 Windows 电脑能安装、完成本机 gh 登录并正常使用；身份切换不会展示上一账号私有数据；不要求团队后台。
- [x] A8（R4、R7）：验证并发修改、权限失效、限流和创建响应丢失；已发现的冲突不能静默覆盖，结果未知时不能盲目重复创建。
- [x] A9（R4、R9）：断网后可查看已缓存详情并保存正文或评论草稿；恢复网络不自行发布，主动提交前检查远端变化。
- [x] A10（R1、R6）：同仓库多工作区在页面内导航只出现一个仓库项，不产生新的主导航图标；首次选定后可一键使用，绑定可修改，目录失效或远端变化时重新选择。
- [x] A11（R6）：已有确认关联时按钮准确回到该聊天；可另建且不覆盖已有草稿，连续误点不重复处理。未取得真实聊天标识时只显示待关联，不用猜测结果冒充已关联。
- [x] A12（R6）：默认开发提示词可编辑，发送前无自动执行；发送后具备读取最新 Issue 和评论的可用路径，提交推送及远端写入边界明确。
- [x] A13（R3、R10）：用户先选定 UI 方向，再确认覆盖列表、详情、编辑/评论、同步/草稿及会话的可交互原型；记录两档桌面尺寸、浅深主题截图、独立视觉评审和 UX 走查结果。正式界面与已确认原型一致；原型不能代替真实集成验收。

## 首版不包含

- macOS、GitHub Enterprise Server、插件内 GitHub 登录、团队后台和跨成员聊天状态共享。
- 捆绑运行时或自动安装 Node、Git、gh、Codex，自动发送任务提示词或创建 worktree。
- 仓库标签定义维护、Issue 与评论删除、离线自动提交。
- Projects、子 Issue 和依赖关系的完整管理能力。
- 宿主原生悬浮仓库导航。已按用户选择改为页面内导航，未来有官方契约时另行评估。

## 不构成验收替代的路径

- 多个全局入口图标不能替代单插件入口；页面内导航不能被描述为宿主原生浮层。
- 手动目录或历史线程扫描不能替代完整桌面项目发现。
- 浏览器模拟宿主、fixture、空仓库读取和生成 URI 不能替代真实集成验收。

## 决策与技术验证状态

业务选择已记录，用户已授权直接进入Trellis实施。A方向与交互原型已经确认，正式管理页已实现并安装0.3.4，当前按上述矩阵继续真实验收。新增需求或宿主验证发现无法满足要求时重新开启相应分支，不悄悄降级。

2026-11-03 用户先澄清原生浮层目标；调查发现通用第三方契约缺失，0.1.3 已修复多个主图标。随后用户明确选择“先用插件内导航，继续完整 Issue 管理”，因此首版范围按 R1/A1 修订。原生浮层未实现的历史结论不改写成已通过。见 [专项调查](research/native-flyout-correction.md)。

分发采用当前仓库独立插件与现有 marketplace 新条目，不合并到 YG Toolkit。动态原生侧栏、完整项目覆盖、工作区草稿及可靠会话关联进入实施第一阶段的能力门槛；已有源码和只读接口证据，但真实端到端尚未验收。最低支持版本以该阶段验证结果限定，不能提前宣称所有 Codex 版本兼容。

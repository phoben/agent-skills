# Tokens 用量统计与 Codex 侧栏

## 目标与授权

用户在Codex侧栏打开YG Toolkit，查看当前账号真实消耗、比较项目逐日投入、进入会话明细。用户已确认C版并明确要求开始Trellis实现和真实接入，沿用该授权执行，不再重复询问同一范围。

## 已确认事实

原插件0.1.4仅有Skills；本机Node24.19、Codex CLI0.163.0。账号接口实测返回每日桶与可匹配本机线程的账号标识。当前索引未提供显式project_id，部分历史缺少账号归属；需要cwd回退分组及历史排除说明。初版交付0.2.1，界面迭代交付0.2.3。

## 需求

- R1：保留原Skills，新增MCP全局侧栏，生产页不显示虚构数据。
- R2：账号总量、每日趋势和额度来自官方接口；缺失值和覆盖不足明确展示，不能补0冒充完整汇总。
- R3：本机仅统计可证明属于当前账号的记录；排除其他账号和身份未知历史，账号切换不返回旧数据。
- R4：固定项目→会话；显式项目优先，缺失时根据cwd及Git共同目录合并worktree为项目。
- R5：采用C版日柱/范围合计/桑基逐行对齐；日柱同刻度；缓存属于输入、推理属于输出，不能重复累计。
- R6：整行查看范围会话、日柱查看单日；子代理只计实际新增并合并合法父会话。支持搜索、排序、分页和分项计数。
- R7：支持本周、近7天、近30天、本月、本季度、本年、自定义；时区统一，周额度保持当前官方窗口。
- R8：加载、空数据、部分可用、失败、账号切换、重试状态清楚；页面说明本机覆盖与排除范围。
- R9：独立插件构建包不依赖原型、工作区node_modules或开发服务器；本地安装后可发现工具、读取页面和查询真实数据。

## 验收

- A1：包外stdio握手、工具发现、global元数据、UI资源及严格参数失败路径通过。
- A2：真实官方用量与额度读取成功，缺失与覆盖不足显示准确。
- A3：跨账号、重复快照、继承历史、子代理、跨午夜和分项守恒测试通过。
- A4：本机真实项目总量=每日之和=桑基分项之和；源数据库和JSONL不修改。
- A5：1440×1000及1280×800界面和日期、范围/单日、搜索排序分页验证通过。
- A6：独立代码审查、构建、测试、本地插件发现及资源验证完成；不能把无法操作的桌面验证虚报为通过。

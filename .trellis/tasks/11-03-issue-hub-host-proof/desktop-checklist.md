# P0 真实 Codex 点检

重要：本清单原先针对多个 global 图标，已被用户澄清否定。以下步骤仅保留历史记录，当前不要继续按旧流程验收或发送验证聊天。现阶段先修成一个主图标；原生悬浮栏缺少第三方接入契约，尚未实现。见 [专项调查](../11-03-github-issue-plugin/research/native-flyout-correction.md)。

本清单用于本机已安装的 Issue Hub 技术验证包。最终安装版本及协议读取结果以 [installed-host.json](research/installed-host.json) 为准；它不能证明桌面渲染已经通过。不会写 GitHub，验证草稿不会自动发送。

## 最短操作顺序

1. 在 Codex 原生侧栏找两个仓库名称，分别点开，确认页面仓库标题及工作区对应各自仓库。若尚未出现新插件，可重新打开 Codex，再继续本聊天。只有“Issue Hub 验证”单一入口不算双仓库项通过。
2. 在其中一个仓库页选择工作区，点击“准备新的验证草稿”，再点“打开草稿／返回聊天”。先确认项目正确、中文多行及首行任务引用完整、尚未发送，已有未发送草稿没有丢失。
3. 若上述结果正确，手动发送这条仅要求回复“宿主验证收到”的验证消息；它明确要求不读改文件、不运行命令、不提交或操作 GitHub。
4. 返回同一仓库页与同一工作区，恢复本机验证请求，再检查关联。等待索引更新后应显示 linked 和真实聊天标识；没有或多个匹配时应等待或显示歧义，不能绑定最近一条。
5. 再点“打开草稿／返回聊天”，应回到刚才的同一聊天。对第二个工作区重复步骤，确认没有串仓库或覆盖草稿。
6. 对照桌面项目与页面计数，检查新增/移除受控项目后“重新发现项目”的行为。记录是否需要重连才能更新原生项；默认只显示两个仓库项，全量发现计数与侧栏数量不同。

现阶段只检查已注册根目录的直接仓库，因此 partial 不能视为所有 GitHub 仓库已覆盖。不要为测试删除项目文件或旧聊天，也无需提供完整私有目录清单或聊天正文。

## 回报方式

可直接回复哪些项通过，例如“两个原生入口正常；草稿项目正确且未发送；关联后能回同一聊天”。失败时说明停在哪一步及页面显示的安全错误即可。

- [ ] 两个原生仓库入口及对应上下文。
- [ ] 项目列表对照与发现覆盖结果。
- [ ] 两个工作区草稿正确、未自动发送、已有草稿保留。
- [ ] 页面重开恢复、唯一关联和返回同一聊天。
- [ ] 动态刷新与重连行为已记录。

结果未收到前保持待点检，P0 不标完成，也不进入 U1 正式方向探索。

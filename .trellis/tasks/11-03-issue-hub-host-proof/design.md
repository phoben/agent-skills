# P0 最小验证设计

父方案：[Issue Hub 技术设计](../11-03-github-issue-plugin/design.md)。当前只实现支持性模块和技术验证页面，界面风格不视作 U1 已确认。

## 模块与范围

- `packages/issue-hub/`：Node 24 ESM，MCP SDK、MCP Apps 与构建工具沿用仓库已验证版本；独立服务、宿主适配、仓库目录、任务关联和相应测试。
- `plugins/issue-hub/`：最小便携及兼容清单、自包含产物与许可，版本独立且一致。
- 当前任务 `research/`：只保存安全的验证摘要、操作步骤与覆盖矩阵，不保存 token、无关聊天正文或完整私有项目列表。
- 本阶段不修改 Tokens 源码、版本或产物，不改现有升版钩子，不接正式 GitHub 管理，不抢先设计用户原型。

## 宿主通道

项目读取另启受限 `codex app-server --stdio`，显式启用实验接口，限制 RPC 方法与响应大小、超时和清理；stdout 只放 MCP 协议。项目目录来自该通道，Git remote 通过无 shell 的固定参数读取，路径与候选在服务端绑定。

只保留一个 global 主入口。仓库诊断工具可保留 app-only 与共享 UI 资源，但没有 global 元数据，不产生主图标，也不是原生浮层子项。目录刷新及工具清单变化只验证诊断目录，不能宣称原生悬浮导航可用。

用户要求的原生浮层在当前公开 SDK 中没有已证实的第三方接入契约。内置首页、资料空间、定时任务和代码审查使用固定 destination/first-party 接入；不得注入注册表、冒用内置插件 ID，或编造 sidebar/list 方法。先修多图标错误，其他导航替代仍需用户明确取舍。

新聊天由服务端从目录键取得路径、重新校验仓库关系，编码为 `codex://new`。打开行为采用依赖注入，测试不操作桌面；Windows 启动路径不得把提示词当 shell 脚本拼接。工具确认后只返回打开请求已发出，不宣称聊天已持久化。

待关联请求持有唯一 nonce、工作区、发起时间和状态；真实查询仅在存在本插件待关联请求时执行。按精确 cwd 与有限创建时间候选读取初始项，nonce 唯一且归属正确才保存已确认 ID，无或多匹配保持未确认/歧义；以 `codex://threads/<UUID>` 返回时不添加 prompt。

## 证据

fixture 仅用于自动测试。真实 CLI 验证记录计数、接口可用性和错误，不输出项目路径或聊天正文。原生侧栏、草稿和关联须用户实际点检，不通过 Windows UI 自动化绕过技能禁止；报告中未通过的行保持 pending。

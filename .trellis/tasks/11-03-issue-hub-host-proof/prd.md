# 验证 Issue Hub 的 Codex 宿主能力

## 目标

实现独立最小 MCP 验证包，检查单插件入口、原生悬浮仓库导航的接入边界、项目发现、工作区草稿与确定性会话关联。

## 授权与边界

用户已在父任务终审后明确要求方案完成即直接进入 Trellis 实施，本子任务承接 P0，无需再次开工确认。正式 UI 仍等待 U1 原型确认；本阶段只做技术验证页面，不代替用户原型选择，不提交、推送或发布。

## 需求

- H1：Issue Hub 只有一个全局主入口。仓库应由插件主入口展开的 Codex 原生悬浮侧栏承载；当前先消除误注册的多个 global 图标，调查通用接入契约。诊断用仓库工具可以保留 app-only，但不能成为主图标或被称作已完成的原生仓库子项。
- H2：提供受限项目/仓库查询与覆盖状态，不能把线程历史或 fixture 冒充完整桌面列表。
- H3：校验选中工作区后构造不发送消息的新聊天草稿深链；首行含本次唯一引用，目录失效或不符时拒绝打开。
- H4：只为本插件发起的待关联请求，在精确工作区和有限候选中核对初始用户项引用；唯一匹配才记录 thread，已知 thread 可通过受控深链返回。
- H5：提供独立、包外可运行的 stdio 服务及最小验证页面、自动测试和真实验证操作说明。真实状态、模拟状态与未验证分别表达。

## 验收

- [ ] V1：包外初始化和 UI 资源可读，恰好一个 global 入口；仓库诊断工具没有 global 元数据。动态工具通知只能证明诊断目录变化，不代表原生悬浮栏已接入。
- [ ] V2：真实 project/list 返回并保存脱敏计数/覆盖结果，对照桌面确认；无历史项目和多路径行为有证据。
- [ ] V3：单一插件主入口展开原生悬浮侧栏，至少两个仓库子项可点击并传递正确上下文；验证刷新和重连。当前没有通用 API 证据，保持未通过。
- [ ] V4：两个受控工作区中的草稿预填正确且未发送，已有草稿不丢失；路径失效被拒绝。
- [ ] V5：成员发送验证草稿后准确绑定真实 thread，重复引用保持歧义，返回已知聊天正确，重复误点不产生重复请求。
- [ ] V6：单元/协议测试、构建及包外验证通过，真实和模拟结果分别记录；所有未验收项明确保留。

## 明确不做

不接 GitHub 写入、Issue 正式管理页面、完整 UI 风格或团队发布，不读取无关聊天正文，不修改 Codex 私有数据库，不替换既有插件。

不注入或修改 Codex 内置路由、注册表，不冒用内置插件标识或专用桥接，不用自绘页面宣称实现原生悬浮栏。用户明确举例的是首页、资料空间、定时任务和代码审查。

Windows Computer Use 技能明确禁止自动操作 Codex 桌面 UI；不得绕过限制另写 SendKeys/UIA/CDP 控制器。可执行 CLI/MCP 协议验证并准备可审阅包，真实宿主交互由用户点检或其他明确受支持且不违反该边界的宿主能力验证，不能以源码或模拟代替。

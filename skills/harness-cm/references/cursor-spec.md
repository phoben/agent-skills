# Cursor 平台规范

## 1. 适用说明

这份文档用于指导把工程化配置迁移到 Cursor 常见结构。Cursor 的规则与 MCP 能力较稳定，但技能、命令、agent、hooks 的文件级规范在不同版本或不同入口中可能不完全一致，因此迁移时需要把“明确支持”和“可替代实现”区分开。

## 2. 作用域与目录

### 项目级

- 工作区目录：`<repo>/.cursor/`
- 项目约束目录：`<repo>/.cursor/rules/`

### 用户级

- 用户配置通常以客户端设置为主
- 若需跨工具共享 skill，可优先使用 `~/.agents/skills/`

## 3. 资源能力矩阵

| 资源类型 | 是否支持 | 项目级位置 | 用户级位置 | 说明 |
|---|---|---|---|---|
| `skills` | 无稳定官方目录 | 建议改写为规则文档、提示模版或共享 skill | `~/.agents/skills/` | 除非用户已有明确 Cursor skill 体系，否则不要假设原生支持 |
| `rules` | 支持 | `.cursor/rules/*.mdc` 或等价规则文件 | 客户端设置或全局规则入口 | Cursor 规则是最稳定的目标之一 |
| `commands` | 无稳定官方目录 | 可改写为提示模版或文档 | 客户端快捷入口 | 不建议做机械迁移 |
| `hooks` | 无统一稳定文件规范 | 按扩展或脚本集成实现 | 用户设置 | 默认视为 `blocked` 或 `rewrite` |
| `mcp` | 支持 | `.cursor/mcp.json` 或工作区 MCP 配置 | 用户设置中的 MCP 配置 | 项目级 MCP 是较适合迁移的资源 |
| `agents` | 无稳定公开目录 | 可改写为规则、提示词或共享 skill | 用户自定义配置 | 默认不做 1:1 迁移 |
| `scripts` | 间接支持 | 仓库脚本目录 | 用户脚本目录 | 通常配合 MCP、规则或外部命令使用 |
| `templates/docs` | 间接支持 | 任意受控目录 | 任意受控目录 | 常作为辅助资产保留 |

## 4. 最小目录示例

```text
.cursor/
├── rules/
│   └── engineering.mdc
└── mcp.json
```

## 5. 迁移注意事项

- 迁往 Cursor 时，优先迁移 `rules` 和 `mcp`，其余类型通常需要改写策略。
- `skills`、`agents`、`commands` 若无明确原生落点，应转为 `.cursor/rules/*.mdc`、共享 `.agents/skills/` 或说明文档。
- `hooks` 缺少稳定的统一文件规范时，不要承诺自动无损迁移。
- 若用户环境中已经存在 `.cursor` 目录，应优先以本地现状为准，而不是死套这份参考。

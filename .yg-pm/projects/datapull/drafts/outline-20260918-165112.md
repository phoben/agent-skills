## 术语表

| 术语 | 定义 | 避免使用 |
|---|---|---|
| DataPull | 面向人类交互、同时可被 Agent 调用的数据库结构文件拉取 CLI | database-schema 技能、导出脚本 |
| DataPull Skill | 检测环境、协助用户安装 DataPull、指导 Agent 安全调用 CLI 的轻量 Skill | DataPull CLI、提取脚本 |
| 引导模式 | 只执行 `datapull` 时进入的中文分步交互流程 | 默认命令、向导脚本 |
| 命令模式 | 通过子命令和参数直接执行操作的非交互流程 | Agent 模式、无人值守脚本 |
| 登记连接 | 保存服务器信息、认证引用与连接安全策略的连接配置 | 登记数据库、数据库实例 |
| 全局连接登记簿 | 当前用户可跨项目复用的登记连接集合 | 项目连接配置 |
| 数据库凭证 | 独立保存、用于数据库身份认证且不得进入日志或结构文件的秘密值 | 连接信息、数据库配置 |
| 目标数据库 | 一次拉取明确选择或输入的真实数据库 | 默认数据库、连接数据库 |
| 数据库对象 | 可用 DDL 表达的表、视图、函数、过程、触发器等命名实体 | 业务数据、数据记录 |
| 结构文件集 | DataPull 按对象类型维护的 DDL 文件集合，不承诺所有类型来自同一时点 | 结构快照、数据库备份 |
| Skill 安装目标 | 用户选择的 Agent 工具与用户级或项目级安装范围组合 | 已检测 Agent、自动发现目标 |

## 已确认的关键决策

1. CLI 源码位于 `cli/datapull/`，以 TypeScript/Node.js 独立构建，Node.js 下限为 `22.12`。
2. 包名为公开的 `@yg-toolkit/datapull`，可执行命令为 `datapull`，升级由 NPM 完成，不提供自更新命令。
3. 默认人类交互优先，同时提供完整命令模式和可选 JSON 输出。
4. 配置与凭证属于用户级全局状态；结构文件属于当前项目。
5. 项目根优先使用 Git 顶层目录，非 Git 场景使用当前工作目录。
6. 新 CLI 复用 `.database-schema/` 名称，但不承担与现有 Skill 的格式或行为兼容。
7. 自定义对象范围按“本次所选类型整体事务”更新，未选择类型保留。
8. 依赖缺失时优先自动安装，但必须先展示计划并取得确认；首版不提供容器备用路径。
9. DataPull Skill 唯一源码位于 `cli/datapull/skill/`，同步到 Plugin 与 NPM 包。
10. CLI 提供硬编码 Agent 清单，不探测是否已安装；首版目标为 Codex、Claude Code、Cursor、Trae IDE。
11. Skill 只提供环境检测、安装协助和调用指导；Agent 不替用户执行全局 NPM 安装，也不接触数据库凭证。

## 明确排除项

- 修改或迁移现有 `database-schema` Skill。
- Python 运行时依赖或对现有脚本的运行时调用。
- `datapull update` 自更新命令。
- Docker 或其他容器化数据库工具备用路径。
- 业务数据、用户、角色、授权、所有权和服务器级配置导出。
- 云 IAM、OAuth、SSH 隧道和跳板机认证。
- TraeCode CLI、未列出的 Agent 工具和完整多语言界面。
- 同一时点完整“结构快照”及历史版本管理。

## 10. DataPull Skill

本章定义 DataPull Skill 的产品边界、分发方式和安装契约。DataPull Skill 是轻量技能，而不是第二套数据库工具；所有数据库连接管理和结构文件拉取均由 DataPull 在引导模式或命令模式中完成。

### 10.1 Skill 的职责与禁止事项

DataPull Skill 应帮助 Agent 在用户提出数据库结构文件拉取需求时完成以下工作：检查 Node.js、NPM 和 `datapull` 是否满足运行条件；在缺少 CLI 时向用户说明影响并给出与当前平台相符的安装命令；协助用户选择安全、明确的命令模式参数；在用户已完成数据库凭证录入后调用 DataPull，并解释其人类可读输出或 JSON 结果。

为保护用户环境和数据库凭证，DataPull Skill 必须满足以下要求。

| 编号 | 要求 |
|---|---|
| FR-015-01 | Skill 必须检查 Node.js 是否不低于 `22.12`，并检查 NPM 与 `datapull` 是否可执行。检查失败时提供中文原因和下一步，而非假装可以运行。 |
| FR-015-02 | 当 CLI 缺失或版本不满足要求时，Skill 必须只给出由用户亲自执行的准确 NPM 安装或升级命令；Agent 不得执行全局 NPM 安装、升级或卸载。 |
| FR-015-03 | Skill 必须提醒用户通过 DataPull 的隐藏输入或本机 `credentials.env` 管理数据库凭证；不得要求用户在对话、提示词、命令行参数或 JSON 中提供密码、Token 或完整含密连接 URL。 |
| FR-015-04 | Skill 可以调用已安装的 `datapull` 命令模式并读取退出码和 `--json` 结果，但不得自行实现连接 CRUD、依赖安装或结构提取。 |
| FR-015-05 | Skill 不得把数据库凭证、结构文件内容或用户的全局连接登记簿发送到第三方服务；不得开启遥测。 |
| FR-015-06 | Skill 必须在执行可能覆盖项目 `.database-schema/` 文件集的 `pull` 前，向用户说明连接别名、目标数据库、对象类型和项目根目录；非交互调用仍须由调用者显式传递 DataPull 所需的确认参数。 |

Skill 的推荐调用顺序为：环境检查 →（必要时）向用户提供安装命令 → 再次检查 → 读取 DataPull 帮助或 `doctor` 结果 → 由用户确认拉取范围 → 调用命令模式 → 按退出码、错误代码和结果路径反馈。用户未完成 CLI 安装、未登记连接或未提供目标数据库时，Skill 应停在相应步骤并给出下一条可执行命令，而不是臆造默认值。

### 10.2 唯一源码、Plugin 同步与 NPM 内置

DataPull Skill 的唯一源码必须位于 `cli/datapull/skill/`。NPM 包和 YG Toolkit Plugin 中出现的 Skill 均为构建产物，不得被视为独立维护源。该约束落实 ADR-0006，并使两种进入路径使用同一份行为说明：用户既可以先安装 `@yg-toolkit/datapull` 再安装内置 Skill，也可以先通过 Plugin 获得 Skill 后由其协助安装 CLI。

| 编号 | 要求 |
|---|---|
| FR-013-01 | 构建过程必须将 `cli/datapull/skill/` 同步至 NPM 包内置资源和 `plugins/yg-toolkit/skills/datapull/` 副本；现有 `plugins/yg-toolkit/skills/database-schema/` 不得被修改。 |
| FR-013-02 | 发布前校验必须比较唯一源码与两个副本的文件清单和内容哈希；任一不一致均阻止发布。 |
| FR-013-03 | Skill 文本必须将 DataPull、DataPull Skill、登记连接、全局连接登记簿、目标数据库和结构文件集作为固定术语使用。 |
| FR-013-04 | Skill 必须明确 DataPull 与现有 `database-schema` Skill 不存在运行时依赖、格式兼容或迁移义务。 |

每个安装副本应携带可机器读取的 Skill 版本和发布内容哈希。内容哈希用于判断用户安装后的副本是否被修改，不能包含数据库连接或其他用户信息。

### 10.3 硬编码 Skill 安装目标

首版安装目标固定为 Codex、Claude Code、Cursor 和 Trae IDE。CLI 仅展示这四个选项，并由用户多选；不得通过检查目录、进程、扩展或登录状态推断任一 Agent 是否已安装。用户选择某项即表示希望安装该项的 Skill。

下表给出首版目标路径约定。Cursor 的用户级和项目级 Skill 路径已由其公开 Skill 文档确认；其余三个工具的路径应在每次发行的兼容性验证门中，对照目标版本官方文档和干净环境实际加载结果确认。未经验证的路径不得在产品界面中表述为“已被 Agent 识别”。

| Skill 安装目标 | 用户级候选路径 | 项目级候选路径（以项目根目录为基准） | 当前状态与验证门 |
|---|---|---|---|
| Codex | `~/.codex/skills/datapull/SKILL.md` | `.codex/skills/datapull/SKILL.md` | 路径来自仓库既有迁移规范；发行前须以受支持 Codex 版本实际发现 Skill 为验证门。 |
| Claude Code | `~/.claude/skills/datapull/SKILL.md` | `.claude/skills/datapull/SKILL.md` | 路径来自仓库既有迁移规范；发行前须以目标 Claude Code 版本的官方文档和实际加载为验证门。 |
| Cursor | `~/.cursor/skills/datapull/SKILL.md` | `.cursor/skills/datapull/SKILL.md` | 已由 Cursor Agent Skills 文档确认；发行前仍须在受支持 Cursor 版本验证发现与调用。 |
| Trae IDE | `~/.trae/skills/datapull/SKILL.md` | `.trae/skills/datapull/SKILL.md` | 路径来自仓库既有 Trae 迁移规范；因缺少本期可复核的官方路径依据，必须通过目标版本官方资料和实际加载验证门后方可启用。 |

说明：`~` 表示当前操作系统用户主目录。若目标平台随后公布其推荐的共享 `.agents/skills/` 路径，首版不得静默改用；应先补充兼容性 ADR、安装矩阵和验收用例，再作为显式新选项发布。

### 10.4 用户级与项目级安装选择

在首次运行引导和 `datapull skill install` 中，CLI 必须按照“先选 Agent，再为每个 Agent 选范围”的顺序提供中文交互。选择多个 Agent 后，用户可为 Codex 选择用户级、为 Cursor 选择项目级，互不影响；CLI 不得用一个全局默认范围覆盖各项选择。

| 编号 | 要求 |
|---|---|
| FR-013-05 | 安装预览必须列出每个 Skill 安装目标、安装范围、绝对目标路径、将创建的目录和将写入的文件。 |
| FR-013-06 | 项目级路径必须从 DataPull 的项目根目录解析规则取得，不能从当前子目录写入。非 Git 目录以当前工作目录为项目根目录。 |
| FR-013-07 | 用户级与项目级可以同时安装同一目标，但 CLI 必须提示可能的工具优先级差异，并在结果中逐项报告。 |
| FR-013-08 | 命令模式必须要求显式 `--scope user` 或 `--scope project`，并支持一个或多个显式 `--target`；未提供 TTY 时不得自行选择范围。 |

### 10.5 目标目录创建与安装回验

当用户选择的目标目录不存在时，CLI 必须先显示预览并在确认后创建所需父目录。目录不存在不得被解释为 Agent 未安装。写入后，CLI 至少应验证 `SKILL.md` 是否存在、YAML frontmatter 是否可解析、名称为 `datapull`、版本与内容哈希匹配，以及文件在预览的目标路径内。

安装失败时，结果应逐项目标显示失败原因、未完成文件和安全的重试命令；已成功目标保持成功状态，不得回滚或删除用户已有目录。若路径为符号链接、不可写目录或解析到项目根目录之外，CLI 必须停止该目标并返回稳定错误代码，不得跟随不受控路径写入。

### 10.6 版本同步、用户修改检测、差异与备份

执行 `datapull skill sync` 或首次运行发现可用的新内置 Skill 时，CLI 必须比较安装副本记录的来源版本、安装时内容哈希与当前文件哈希。

| 安装副本状态 | 默认动作 | 可选动作 |
|---|---|---|
| 不存在 | 提示安装 | 安装、跳过 |
| 未修改且内置版本更新 | 显示变更摘要后升级 | 升级、跳过 |
| 内容与安装时哈希不同 | 停止覆盖并标记“用户修改” | 查看差异、备份后覆盖、取消 |
| 无法读取或缺少元数据 | 不覆盖 | 查看诊断、按新安装处理（需确认） |

`--force` 仅允许在命令模式中与目标和范围一起显式指定，并且必须先生成带时间戳、位于同一安装根目录的可恢复备份；备份创建失败时不得覆盖。差异输出必须限于 Skill 文件内容，不得读取或输出邻近目录中任何秘密文件。

### 10.7 先装 Skill 时的 CLI 环境检测与安装协助

用户可能通过 YG Toolkit Plugin 先获得 DataPull Skill。此时 Skill 必须首先判定当前环境是否具备运行条件，并以用户可复制的形式提供后续动作：

```text
Node.js >= 22.12：通过 / 不通过
NPM：通过 / 不通过
@yg-toolkit/datapull：已安装版本 / 未安装
建议命令：npm install -g @yg-toolkit/datapull
```

Agent 只解释和展示命令，由用户在其终端执行。用户报告安装完成后，Skill 可以重新执行版本检查；未验证成功前不得继续指导数据库拉取。若全局安装因企业策略、无权限、代理或包源不可用而失败，Skill 应保留原始错误的脱敏摘要，并提示用户依据其组织 NPM 政策处理，不能建议关闭 TLS 校验或使用不明镜像。

## 11. 非功能需求

### 11.1 中文优先与英文稳定接口

引导模式、帮助、确认提示、进度说明和面向人类的错误解释必须采用简体中文。命令、子命令、选项、JSON 字段、错误代码和退出码必须采用稳定英文标识。中文文案调整不得改变 JSON 字段、错误代码或退出码语义。

| 编号 | 非功能要求 |
|---|---|
| NFR-004-01 | 不带参数执行 `datapull` 时，中文引导模式为默认体验；输入无效时给出可恢复的中文说明而非堆栈。 |
| NFR-004-02 | 非 TTY 环境不得显示菜单、动画或隐藏输入提示；必须要求完整命令参数，并建议 `--json`。 |
| NFR-004-03 | 帮助命令必须展示适合复制的最小示例、数据库凭证不进入参数的说明和风险操作的确认规则。 |

### 11.2 跨平台兼容矩阵

首版支持 Windows 10/11、macOS、Ubuntu LTS、Debian Stable 和 Fedora 当前稳定版。支持意味着在该系统上可完成 NPM 安装、中文或降级交互、全局连接登记簿读写、三类数据库工具检测、在用户确认后调用指定包管理器、结构文件拉取和 Skill 安装；不是对任意终端、任意 Linux 发行版或任意数据库客户端版本的无条件承诺。

| 平台 | 自动安装候选包管理器 | 首版验证要求 |
|---|---|---|
| Windows 10/11 | `winget` | 验证 PATH 刷新提示、UAC/权限说明、PowerShell 与 SQL Server 官方组件检测。 |
| macOS | Homebrew | 验证 Intel 与 Apple Silicon 的可执行工具发现和权限说明。 |
| Ubuntu LTS、Debian Stable | `apt` | 验证非 root 用户的提权提示和官方工具包命名。 |
| Fedora 当前稳定版 | `dnf` | 验证包命名、提权提示和工具版本检测。 |
| 其他 Linux | 不自动安装 | 仅检测、报告和提供手工指引。 |

自动安装前必须展示工具、来源、命令、权限和下载影响并要求确认。命令模式只有使用显式安装授权参数时才可调用包管理器。无法识别包管理器、安装失败或需要超出已说明权限时，必须中止安装并提供手工指引。

### 11.3 安全、隐私与日志脱敏

| 编号 | 非功能要求 |
|---|---|
| NFR-002-01 | 数据库凭证只能由隐藏输入写入用户级 `credentials.env`，或由运行进程提供；不得保存到 `config.json`、项目目录、结构文件、命令行参数、日志、诊断包或 JSON 结果。 |
| NFR-002-02 | CLI 必须尽力将秘密文件限制为当前用户可读写；无法设置平台权限时必须以警告结果告知用户，不得声称已加密。 |
| NFR-002-03 | 数据库连接必须使用最小只读权限。SQL Server 默认启用传输加密和服务器证书验证；证书不可信时不得自动关闭加密或静默接受证书。 |
| NFR-002-04 | 所有外部工具调用必须使用参数数组或等价安全机制，不得拼接未验证的连接别名、数据库名、对象名或路径为 Shell 命令。 |
| NFR-002-05 | 日志和 JSON 错误只输出脱敏后的主机、端口、连接别名、对象类型和诊断分类；密码、Token、连接 URL 中的秘密部分和环境变量实际值必须替换为掩码。 |
| NFR-002-06 | 不得导出业务数据、账户、角色、授权、所有者、`DEFINER` 或服务器级配置。 |

### 11.4 性能、响应性与大库处理

DataPull 应先列出任务清单，再逐对象类型或可报告的子任务更新进度。无法精确衡量的数据库官方工具阶段必须显示明确阶段名、已用时间和取消状态，不得显示伪造百分比。引导模式在普通终端中应在用户完成输入后尽快显示校验开始和任务状态；长任务不得长时间无输出。

对大型数据库，CLI 必须采用流式写入或临时目录，避免将完整 DDL 无界累积到内存。每个 `pull` 在所选对象类型全部成功前不得覆盖对应正式目录；取消、进程中断或磁盘空间不足时清理自身临时状态并保留先前结构文件集。超时、并发度和内存预算的默认值及可配置边界属于实现设计，但必须在发布前基准测试中记录。

### 11.5 可访问性、无颜色和窄终端降级

交互 UI 不得只依赖颜色表达错误、选择或进度；状态必须同时以文字和符号表达。应支持 `NO_COLOR`、`--no-color` 和非 TTY 的纯文本输出。窄终端须换行显示绝对路径和长错误说明，不得截断用户确认所需的工具来源、命令、权限或覆盖影响。所有选择控件必须能仅用键盘完成，并在取消时明确说明不会写入结构文件集。

### 11.6 可维护性、依赖许可与配置迁移

CLI 必须以 TypeScript/Node.js 独立实现，开启严格类型检查；不得在运行时调用 Python 或现有 `database-schema` Skill 脚本。业务规则、终端 UI、外部工具适配、文件事务、配置读写和 Skill 安装应可独立测试。`config.json` 必须带有版本字段；遇到可迁移的旧版本时，CLI 在备份后执行确定性迁移，遇到未知字段、损坏 JSON 或不可安全迁移的数据时停止并提示用户修复，不能静默丢弃。

引入的 NPM 依赖必须具有与公开发布兼容的许可证，并在发布构件中保留许可证和第三方声明。数据库官方工具的安装来源、包名和版本规则应由可测试的适配表维护，不能散落在交互文案中。

### 11.7 无遥测与网络访问边界

DataPull 首版不采集遥测、使用统计、数据库元数据或数据库对象内容。网络访问仅限于：用户确认后由系统包管理器获取数据库工具、用户执行 NPM 安装或升级、以及用户明确配置的数据库连接。CLI 不得在启动、`doctor`、Skill 安装、配置校验或错误报告时静默联网，也不得上传诊断结果。

## 12. 质量保证与验收

### 12.1 测试层级与契约测试

验收必须区分静态检查、单元测试、真实数据库集成测试、跨操作系统验证、交互终端验证、发布包验证和实际 Agent 发现验证；任一层通过均不能替代其他层。

| 测试层级 | 最低验收内容 |
|---|---|
| 单元测试 | 配置版本迁移、凭证脱敏、文件名规范化、稳定短哈希、路径边界、覆盖事务、错误代码映射和 Skill 修改检测。 |
| 契约测试 | 命令帮助、必需参数、JSON Schema、退出码、错误代码、非 TTY 拒绝交互、`--yes` 的副作用边界。 |
| 集成测试 | 三类真实数据库的连接、枚举/手工目标数据库、对象提取、只读限制、TLS 失败和官方工具缺失场景。 |
| 端到端测试 | 引导模式七阶段、失败恢复、依赖确认式安装、取消、成功结果和所选类型整体覆盖。 |
| 发布测试 | `npm pack` 内容、二进制入口、Node.js 下限、唯一 Skill 源码与 NPM/Plugin 副本一致性。 |

### 12.2 三数据库真实集成测试

每种数据库至少准备一个受支持版本的隔离测试实例和最小只读账户。测试实例必须包含共同对象和该引擎特有对象；测试数据可以存在以证明不被导出，但验收构件中不得包含敏感业务数据。

| 引擎 | 必测对象 | 必测安全和失败场景 |
|---|---|---|
| MySQL | 表、视图、函数、过程、触发器、事件 | 无权枚举数据库但可手工输入、无权读取元数据、含 `DEFINER` 的 DDL 已清理。 |
| PostgreSQL | schema、扩展、表、视图、物化视图、序列、函数、过程、触发器、类型 | 同名不同 schema、函数重载、不可访问 schema、扩展或所有者信息排除。 |
| SQL Server | schema、表、视图、函数、过程、触发器、序列、同义词、类型 | Windows 集成认证、用户名/密码、证书不可信时连接被拒绝且不建议关闭加密。 |

数据库版本支持以厂商仍处于官方支持期的版本为政策范围。每个正式版本必须在发布说明中列出实际验证的服务端版本、客户端版本、操作系统和已知限制；未实际验证但仍在政策范围内的版本只能标记为“计划兼容”，不得标记为“已验证”。

### 12.3 三操作系统安装与拉取矩阵

### 12.4 交互终端、非 TTY 与 JSON 验收

以下场景采用 Given/When/Then 作为最低验收标准：

1. Given 已登记连接且依赖齐备，When 用户仅执行 `datapull`，Then CLI 依次完成连接选择或新增、连接校验、目标数据库选择或输入并校验、对象范围选择、进度、结果和结束；默认对象范围为当前引擎全部可用对象。
2. Given 连接校验、目标数据库校验、依赖检测或拉取任一步失败，When 用户查看恢复选项，Then 已填写内容被保留，并能重试当前步骤、修改相关信息、返回连接选择或退出；退出不会改写目标对象类型目录。
3. Given 标准输出不是 TTY，When 仅执行 `datapull` 或缺少必需参数的命令，Then CLI 不显示菜单，不读取隐藏输入，返回稳定参数错误及可复制命令示例。
4. Given 调用者使用 `--json`，When 命令成功、失败或取消，Then 标准输出仅包含一个符合 JSON Schema 的结果对象，诊断文本写入标准错误且不含秘密。
5. Given 用户选择表、视图和函数，且函数提取失败，When 拉取结束，Then 三个对象类型的既有正式目录均不发生改变；未选择的对象类型同样保留。

### 12.5 安全测试

安全验收至少覆盖：带密码 URL、环境变量、命令参数、异常堆栈和子进程错误输出的秘密脱敏；连接别名、数据库名、schema、对象名和输出目录的路径穿越拒绝；含 Shell 元字符输入不能触发额外命令；符号链接和目录替换不能导致写入项目根目录之外；`credentials.env` 的权限设置与降级警告；SQL Server 无效证书拒绝；以及没有业务数据、角色、授权、所有者或 `DEFINER` 出现在结构文件集中。

### 12.6 Skill 安装、同步和冲突保护测试

每个 Skill 安装目标都应验证用户级和项目级路径预览、确认后创建、正确写入、frontmatter/哈希回验、失败的逐项结果和不会检测 Agent 安装状态。对于 Codex、Claude Code、Cursor、Trae IDE，测试报告必须分别记录以下结论：路径文件校验是否通过、目标版本中实际发现 Skill 是否通过、实际调用是否通过、未通过的原因。

其中 Cursor 的官方文档已明确列出 `.cursor/skills/` 和 `~/.cursor/skills/`；Codex、Claude Code 和 Trae IDE 的发行验收必须保留当期官方路径依据及实际加载证据。若任一目标的官方路径或发现行为无法确认，该目标不得在该版本中宣称可用，应在 CLI 中标注为不可用并提供诊断，而非静默写入。

同步保护验收必须覆盖未修改副本升级、用户修改副本阻止覆盖、差异查看、备份成功后的强制覆盖、备份失败拒绝覆盖，以及唯一源码、Plugin 副本与 NPM 包内置副本的哈希一致性。

### 12.7 发布包内容与 Plugin 副本一致性检查

发布前必须在干净目录执行 `npm pack` 并检查：包名为 `@yg-toolkit/datapull`、二进制命令为 `datapull`、Node.js 引擎下限为 `22.12`、不包含用户配置或凭证、包含内置 DataPull Skill、包含必要许可证声明，且不包含 Python 运行时或现有 `database-schema` Skill 的运行时副本。发布流水线必须阻止未经验证的目录适配、未同步 Skill 或未通过测试的构件进入公开 NPM Registry。

## 13. 实施约束、风险与后续范围

### 13.1 首版交付清单

首版交付物为公开 NPM 包 `@yg-toolkit/datapull`、位于 `cli/datapull/` 的独立 TypeScript/Node.js 源码、内置 DataPull Skill、同步到 `plugins/yg-toolkit/skills/datapull/` 的副本、跨平台官方工具适配表、自动化测试和发布说明。现有 `plugins/yg-toolkit/skills/database-schema/` 是明确保护项，不属于本期改动范围。

首版功能必须覆盖：引导模式和命令模式；全局连接登记簿与独立数据库凭证；MySQL、PostgreSQL 和 SQL Server 的只读结构提取；动态对象范围；确认式工具安装；事务覆盖；分层命令、JSON、退出码和错误代码；以及四类硬编码 Skill 安装目标。CLI 不提供 `datapull update`，用户通过 NPM 完成升级。

### 13.2 主要风险与缓解措施

| 风险 | 影响 | 缓解措施与验收证据 |
|---|---|---|
| 数据库客户端、包名或系统包管理器随平台变化 | 自动安装失败或导出不一致 | 将适配数据集中维护；安装前预览；未知平台仅指引；保存各支持平台实际验证记录。 |
| Agent Skill 路径或发现机制演进 | 写入成功但 Agent 不加载 | 使用硬编码适配器和发行验证门；未证实目标不宣称支持；以官方资料和实际加载记录为依据。 |
| 凭证泄露 | 数据库或企业环境暴露 | 独立秘密文件、隐藏输入、权限控制、全链路脱敏、禁止命令参数传密和安全回归测试。 |
| 部分拉取覆盖旧文件 | 结构文件集混合或损坏 | 临时目录、所选类型整体事务、失败回滚、锁与中断清理；文案不称其为同一时点结构快照。 |
| 大库或厂商工具输出异常 | 内存耗尽、长时间无响应、错误 DDL | 流式处理、进度阶段、取消、基准测试和三引擎真实集成测试。 |

### 14.4 命令示例与 JSON 结果示例

以下是稳定接口形态示例，实际选项说明以 `datapull --help` 为准。示例不包含数据库凭证。

```bash
# 人类交互入口
datapull

# 新增登记连接；密码由隐藏输入写入数据库凭证，不作为参数传入
datapull connection add --name yuga --engine postgresql --host db.example.internal --port 5432 --credential-var YUGA_DB_PASSWORD

# 诊断本机运行环境和数据库工具
datapull doctor

# 非交互拉取：明确连接、目标数据库、对象类型与 JSON 输出
datapull pull --connection yuga --database res-v4 --include table,view --json

# 安装多个 Skill 安装目标；范围必须显式指定
datapull skill install --target codex --target cursor --scope project

# 对用户修改的 Skill 副本，在已确认备份策略后强制同步
datapull skill sync --target codex --scope user --force --yes
```

成功 JSON 示例：

```json
{
  "ok": true,
  "command": "pull",
  "connection": "yuga",
  "database": "res-v4",
  "includedObjectTypes": ["table", "view"],
  "outputDirectory": "E:/work/app/.database-schema/yuga/res-v4",
  "updatedObjectTypes": ["table", "view"],
  "preservedObjectTypes": ["function", "procedure"],
  "error": null
}
```

失败 JSON 示例：

```json
{
  "ok": false,
  "command": "pull",
  "connection": "yuga",
  "database": "res-v4",
  "updatedObjectTypes": [],
  "preservedObjectTypes": ["table", "view", "function", "procedure"],
  "error": {
    "code": "EXTRACTION_FAILED",
    "message": "函数提取失败，已保留本次所选对象类型的既有文件。"
  }
}
```

稳定退出码和错误代码最小契约如下：`0` 成功；`2` 参数或非 TTY 交互错误（`INVALID_ARGUMENT`）；`3` 配置或凭证引用错误（`CONFIG_INVALID`）；`4` 运行时或数据库工具前置条件缺失（`PREREQUISITE_MISSING`）；`5` 连接认证或 TLS 校验失败（`CONNECTION_FAILED`）；`6` 目标数据库不可访问（`DATABASE_UNAVAILABLE`）；`7` 结构提取失败（`EXTRACTION_FAILED`）；`8` 用户取消（`CANCELLED`）；`9` 文件事务、锁或 Skill 冲突（`CONFLICT`）；`1` 未分类内部错误（`INTERNAL_ERROR`）。新增错误代码不得改变既有代码语义。

# 安全接入与验收

使用当前环境的 `trellis --help`、`trellis init --help`、`trellis update --help` 和实际平台列表核对命令参数。未安装时，核对 Trellis 官方发行渠道及安装范围，在批准后执行。安装 CLI、注册项目平台和选用流程分别验证。

| 项目现状 | 接入方式 |
| --- | --- |
| 尚未接入 | 核实目标目录后，用官方 init 生成用户选择的平台。按批准的默认方案和实际模板继续完善项目流程 |
| 已有 Trellis，缺平台 | 先核对目标版本是否能增量接入。需预览时在隔离目录用官方入口生成，逐项核对允许合入的配置和现有文件，报告合并冲突和官方注册情况 |
| 已有流程，仅调整节点或变体 | 按现有规范定位生效文件，预览范围，保留任务绑定与既有主干流程 |
| 依赖、宿主信任或模型不可用 | 报告具体缺口，完成其余已授权动作。原生回退或人工核验按实际能力记录 |

接入前保留用户自定义 workflow、spec、任务、平台配置及与本轮无关的改动。使用实际官方命令生成原生能力并核验登记；避免整目录覆盖、手工伪造管理哈希或复用另一项目的本地状态。变体库、团队默认和当前任务选择分别预览。配置和安装部分成功时只恢复缺项。

## 验收场景

- 空白项目能找到目标宿主和一条可用默认流程。已有项目仍能读取原规则、任务和其他平台配置。
- 动态发现能反映变体增删，现行默认与已有任务 pin 可分别回读。缺失选择会提示异常。
- 指定宿主能加载项目入口。用隔离任务核验角色、技能、注入的任务及规范。验证记录区分配置存在、Hook 回放与真实新会话的实际能力。
- 模拟一个典型事项沿批准、实施、验收和交付的节点走读。客户数据、真实模型账单、GitHub 写入等需要相应授权的验证按批准范围执行。仅有本地结果时，明确列出未核实的真实宿主或远端环节。

# 流程设计与发现

## 项目文件各放哪里

| 内容 | 位置和用途 |
| --- | --- |
| 默认流程 | `.trellis/workflow.md`，记录节点、批准与交付规则 |
| 可选变体 | `.trellis/workflows/<id>.md`，各自描述适用场景、流程和门槛 |
| 长期规则 | `.trellis/spec/`，记录本项目技术、验收及执行约束 |
| 项目自建的 Trellis 工具 | `.trellis/scripts/project/`，保留原生脚本的现有入口 |
| 当前事项的工件 | 用已经获准创建的任务目录或档案，遵循项目现有记录方式 |

每个变体的首个 H1 导语和首个 H2 写清适用场景、选择后会发生什么及主要交付。节点写清触发、责任人、必需工件、证据和回退点。比如日常修复按规划、实施和验收推进，PR 冲突变体还需核对原 PR 两端、复验双方受影响行为。流程复杂度以项目实际需要为准。

技能路由说明何时使用、谁调用、缺少时怎么恢复。按实际宿主分别记录原生角色、模型及强度。型号以当前生效 workflow 和已批准覆盖为准。Codex 与 Claude 可共享业务步骤，由各自原生入口加载角色和验证参数。检查实际执行需看宿主回执，派发参数和 Hook 重放各自单独记为证据。

## 只读发现

从目标项目动态读取，多个技能共用同一工具：

```text
node <trellis-setup技能目录>/scripts/workflow-tools.mjs discover --root <项目>
node <trellis-setup技能目录>/scripts/workflow-tools.mjs discover --root <项目> --task <已有任务或档案路径>
```

默认只读本地。确认需要查 CLI 模板目录时可加 `--templates`，插件目录的版本和当前宿主是否能读取以实际结果为准。不能运行工具时直接核对目标项目及 CLI 帮助，并说明缺项。

原生选择顺序是任务 pin、个人、团队、全局。已有任务用原绑定，查不到或失效时报告诊断，不能把回落当原选择已生效。CLI 提供的模板、已保存变体、团队默认和任务绑定各是不同状态。只读首个真实 H1 及导语和首个 H2 内容，跳过 frontmatter、注释和围栏伪标题，摘要不足再定向补读。新增、删除、改名后重新发现。依据事项实际诉求推荐，避免固定 Issue Type 到变体 ID 的映射。选择或保存流程按相应授权执行。 已接 Issue 管理的项目若为新变体补充受管分流入口，由 issue-init 预览并按授权添加。流程发现仍直接读取当前目录。

## 与 Issue 技能的交接

- `trellis-setup → issue-init` 提供目标项目、当前默认流程、可用变体、实际宿主、验证证据和缺项。Issue 分类、授权、标签、表单及来源入口由 issue-init 单独确认。
- `issue-init → trellis-setup` 提供已选 Trellis 的目标仓库、现有流程、拟使用的宿主、待补项和已获授权范围。接入完成后回到 Issue 配置的未完成处。
- `issue-triage → 项目主会话` 提供已核实的 Issue 身份、关联任务或档案、当前活动任务保护、所选流程及可用状态、下一节点和用户批准范围。任务创建、绑定、规划和实施由项目入口推进。

# 验证与记录

## 1. 分层验证

按实际影响分别执行并如实报告：

- 后端编译、相关单测或数据库迁移检查。
- PC 前端、移动端的类型检查、测试或构建。
- Skill frontmatter/结构校验、Markdown 引用解析和触发边界复核。
- Hook/脚本语法检查及最小行为验证。
- 配置、部署或运行时改动的对应环境验证；未执行的层明确标为未验证。

不要用静态检查代替数据库、浏览器、部署或远端 Git 验收。

## 2. Harness 报告

单独列出：

- 引入的工具型能力及验证证据。
- 从规范型内容提炼的规则、项目事实依据和 Spec 落点。
- 跳过的 Trellis/Harness 基础设施及等价本地能力。
- 被阻断的框架同步类能力及来源路径。

## 3. 同步历史

仅在用户授权更新同步元数据后修改 `.framework-sync.json`。记录来源范围、已融合、已跳过、已提炼规范、待决项、特殊处理和验证结果。

`lastCommit` 只能前进到最高的连续已处理提交：提交中的所有文件必须已融合、明确跳过、完成规范提炼或以可追溯方式处理。仍有未决文件时，不得越过该提交伪造“同步完成”。

提交、推送、部署和任务归档均需各自授权；本地验证通过不代表这些动作已获许可。

完成标准：报告能从上游提交追踪到本地结果，验证层次和未验证风险清楚，同步基线与实际处理范围一致。

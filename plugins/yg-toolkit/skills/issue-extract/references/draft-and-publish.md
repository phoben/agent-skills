# 评估、需求正文与发布契约

起草或发布时读取。两个交付面分开维护：审核评估可以包含实施建议；真实 Issue 默认只澄清需求。它们共享原始依据和范围，不共享所有内部内容。

## 审核评估

每条可按下列字段组织，短任务可合并表达，不为填表补造内容：

| 字段 | 应回答的问题 |
| --- | --- |
| 临时编号及标题 | 用户如何稳定地选择这条任务？ |
| 原始诉求 | 谁在什么情况下需要什么结果，原文在哪里？ |
| 当前事实 | 实际项目已有何能力、测试或方案，证据适用哪个版本？ |
| 真正缺口 | 是未实现、部分实现、具体缺陷、规则未决，还是尚未验证？ |
| 去重结论 | 哪条已有任务/Issue/方案相近，为何新增或归并？ |
| 实施建议 | 能复用什么、增量到哪里、怎样验证；哪些只是建议？ |
| 交付与验收 | 哪份代码/测试/文档及可观察业务结果可以证明完成？ |
| 前置与问题 | 缺哪些业务输入，有何依赖和范围限制？ |

同时给出剔除/合并清单。典型判断：

- “培训现场人员”排除；只有确需交付操作说明时才另评估文档任务。
- “补齐所有回归”不足以单列，需定位实际漏测路径或失败场景。
- “已有方案但没实现”优先检查实际功能缺口，不再建议从零编写同义方案。
- “菜单已有”不证明业务已实现；“Issue 关闭”不证明当前版本满足本次场景。
- 需求方提出某个技术做法时，保留其原话与目的，区分明确约束和建议；不把建议无条件写成需求。

## 拟发布正文

根据类型取舍下列结构，保留业务可理解的场景。正文语言跟随用户；示例字段名不要求逐字照搬。

```markdown
## 背景与目标
谁在什么操作下遇到什么问题，希望获得什么业务结果。

## 原始依据
原资料名称、时间/版本、真实链接及章节/页码/录音或消息定位。
概括已确认的讨论结果；建议、分歧和当时进度单独注明。

## 当前情况与需求范围
简述核对后的已有能力与增量边界；写清需要什么结果。
缺陷补充环境、复现条件、实际结果与预期结果，以及是否实际复现。
文档/设计任务明确交付物和工程用途，不在建单时预先完成解决方案。

## 验收场景
用具体输入、操作和可观察结果定义完成；覆盖关键反例。
会议直接确认的规则和新增验收建议有所区分。

## 待澄清与前置
只列会改变范围、行为或验收的未知项；不代业务方决定规则。
方案型交付可列明未知项及其影响，不把获得线下回复作为 Agent 的产物。

## 关联与范围边界
相关资料或真实平台 Issue、依赖及本条不承担的相邻工作。
```

正文是接手者可独立理解的需求，不依赖当前聊天里的临时编号或隐含上下文。用可访问的一手来源支持关键规则；缺少可发布链接时提供必要的原意摘要与定位，并说明本地归档可用性。

保留业务名称及必要错误信息，去掉与理解需求无关的函数、表结构、接口建议和实现步骤。用户明确要求技术 Issue 时可保留相关内容，仍区分需求、现状与建议。当前用户要求“澄清需求，不做方案”时，以此为发布边界。

## 创建前检查

确认以下信息在现有授权中已明确；能继承的内容不重复询问：

- 托管主机、目标仓库及获批临时编号；用户选定范围与本轮最终正文相符。
- 原始资料、项目现状与相关平台记录是否有会改变判断的新信息。
- 获批正文采用需求版还是用户要求的技术版。格式整理、来源补充及用户明确要求的改稿可直接完成；实质扩大范围或改变行为须重新确认。
- 是否包含未获批准的负责人、标签、里程碑、依赖关系等额外写入；没有授权则省略。

先把最终内容准备成结构化参数或本地正文文件。用 CLI 时通过正文文件提交多行内容，避免转义失真。平台名称、工具参数及关系能力按实际发现的工具/帮助确定，不写死某一种 MCP 或 CLI。

## 创建与恢复

在内存或允许的归档位置维护逐条记录：临时编号、目标仓库、最终标题/正文、获批范围、创建结果及回读状态。它是恢复依据，不要求项目增加固定配置或专用状态库。

1. 发布前查相关已有单及同批次成功记录。用户只选部分条目时，其他条目即使被称为“前置”也只保留业务问题，不自动补建。
2. 按实际能力创建选中条目，取得真实编号与链接后再填写后续关联。若某前置条目未成功，暂不写无效关联，不另造目标。
3. 回读并比较标题、完整正文及获批属性。正文截断或回读失败标记为未核实，不报告验证成功。
4. 发生超时、连接中断或未知响应时，先按目标仓库、标题、正文特征及创建时段查询实际结果。确证已经成功则恢复原记录；确证未创建且原因可修复时，只补该项。
5. 无法判定是否创建时停止该项写入并报告。其他独立且仍获授权的条目可继续；批量部分成功分别列明，禁止整批重放或删除成功结果来重来。

发布成功不代表开始编码。最终给出真实 Issue 链接、临时编号映射、未完成或未核实项，以及用户还需决定的业务问题。只在获授权的文档范围内更新索引或登记结果，不顺带发布资料、改动代码或调整旧 Issue。

# 定向现状核验委派契约

仅在需要派发核验子代理时读取。使用平台现有代理能力，不假设本文件会自动注册一个可执行代理类型。

## 主 Agent 提供

- 目标项目、版本线索和具体核验问题；候选诉求及最相关的原始资料定位。
- 可读取的业务领域、相关规范，以及已有核验记录，避免重叠扫描。
- 只读边界、允许的无副作用验证和证据交付位置。其他会话可能同时修改项目，保留他者改动。
- 若允许保存报告，指定唯一文件归属；用户仅要对话时，直接返回结果，不擅自创建文件。

给出待核实的命题，不预先要求代理证明“功能缺失”或保留某条 Issue。独立领域可并行，共同身份/数量等跨域规则需在主会话统一。

## 子代理核验

1. 按仓库导航约定定位实际业务文件，核对当前页面入口、调用关系和终态行为。相关代码不等于用户已经能够完成目标操作。
2. 查现有方案、活跃/归档任务、测试及已有核验；留意占位菜单、演示组件、历史快照、已退役路径和未提交实现。
3. 验证应解决一个影响提取判断的具体问题。可运行现有、隔离、无业务副作用的定向检查；不修改代码或配置来制造通过，不操作真实业务数据、设备和外部写接口。
4. 来源中的约定、项目当前事实和自己的判断分别报告。无法访问的系统或版本列缺口，不以关键词零命中直接下结论。

## 返回结果

按每个诉求返回：

- 原始依据及适用版本；当前已具备的能力与真实缺口。
- 证据位置与关键内容：实际路径/提交/行号、页面或接口入口、文档章节、已有任务/Issue 链接。
- 已执行检查的命令、结果、数量和边界；仅存在的测试明确标注未运行。
- 建议保留、删除、收窄或归并到哪里，以及理由。
- 若保留：可由 Agent 交付的产物、基于现状的实施建议、验收反例、依赖和未决业务输入。
- 信心不足或证据冲突之处；下一步最小核实动作。

只返回完成上述判断必需的内容，不扩展为全仓审计、修复、完整设计或线下工作计划。主 Agent 负责最终筛选及对外写入。

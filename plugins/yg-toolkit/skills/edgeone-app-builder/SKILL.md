# EdgeOne 应用构建与更新

为 EdgeOne Pages／Makers 新建应用，或在现有项目中完成用户要求的更新，并交付能按目标部署方式运行的成品。业务功能、技术栈、数据使用及历史版本行为由应用需求决定；本技能负责尊重应用现状、处理 EdgeOne 部署兼容与交付质量。

## 定位项目并了解现状

若用户指定现有应用或项目路径，以该路径为准。未指定时，从当前工作目录、已打开文件、任务描述和会话上下文中定位来源项目；只有定位结果唯一时才直接使用。若多个项目都可能是目标，询问用户选择，避免修改错误项目。

接手已有项目后，先检查项目级指令、构建配置、依赖清单和锁文件、运行入口、路由、样式体系、组件库及已有测试。了解哪些行为与目录属于应用自身，再结合接收方部署规范确定：

- 独立站点还是聚合站子路径；正式访问基址、应用标识，以及是否需要保留版路径。
- 静态输出、服务端渲染、平台函数、外部服务，或它们的组合。
- 构建环境与线上运行环境各自需要的版本、依赖、环境变量和资源绑定。

从项目和会话确定常规选项。只有无法确认且会改变成品兼容性的事项才询问用户，例如独占 `/` 还是挂载到已有站点下。未知账号能力或资源绑定记为待核实，不据此声称能够部署。

## 选择可运行的交付方式

更新已有项目时，默认沿用其技术栈、框架版本、UI 框架、组件库、样式方案、目录组织与既有约定，只在完成需求所需的范围内修改。用户明确要求改变这些选择时，再按该要求调整。

不要为了局部功能更新顺手替换框架、重做界面体系、升级无关依赖或重写项目。现有约定与用户需求冲突，且会影响兼容性、维护成本或用户体验时，先说明影响并确认必要调整。

- 保留项目已有技术选择，优先完成必要的 EdgeOne 适配，不为统一部署而重写业务或强制改成静态站点。
- 新建项目时按需求与部署目标选择合适技术方案；避免把既有项目的约定误当成新应用的强制模板。

- 静态应用交付构建后的页面与资源；需要在线执行的代码交付相应平台运行产物，或明确外部服务依赖。
- 使用函数、SSR、框架适配器、原生依赖或持久化服务时，按需阅读 [运行方式与平台边界](references/runtime-and-platform.md)。普通静态应用无需加载全部运行时细节。
- 查阅当前官方文档确认所用能力、配置和配额；参考资料中的目录示例不是平台能力的穷尽列表。账号或框架版本未验证的支持情况如实标注。

只有前端文件不足以交付完整功能时，说明还需要哪些服务与配置；不要以本地开发服务器正常运行替代部署兼容验证。

## 控制更新范围

将用户描述转成明确的页面、功能或部署变更范围。优先复用现有组件、设计 token、路由和数据流；保持未涉及的页面行为与业务规则。涉及共享样式、全局路由、依赖升级、目录迁移或配置重构时，核对其影响是否超出本次需求，再决定如何实施或向用户说明。

## 适配实际挂载位置

以目标路径检查资源基址、客户端路由、服务端路由、接口地址、重定向、附件及懒加载资源。独立站点可以使用根路径；聚合站应用以接收方分配的路径为准。

- 保留现有多页、hash 或 history 路由，验证直接打开深层链接与刷新；回退规则要保留真实资源和接口的响应语义。
- 子路径应用检查 Cookie、浏览器存储、Service Worker 作用域，以及配置对其他应用的影响；需要共享的状态由应用显式声明。
- 接收方要求历史路径时，验证成品能在该位置运行，或为对应基址生成成品。归档不自动改变提交、编辑或数据逻辑。
- 多应用共用项目时，把全站路由、响应头、中间件和运行配置变更作为待合并配置交付；多个框架的输出不能默认通过复制目录完成合并。

## 构建并验证成品

执行项目实际的可复现构建，记录使用的版本与命令。验证构建输出和平台运行产物，而不只检查开发模式。

在匹配目标挂载位置的本地预览或已获准的测试环境中检查：入口、直接访问深链、刷新、脚本与样式、图片字体、懒加载和适用的下载、接口或 SSR。观察响应内容与错误；返回了 HTML 的脚本请求不算资源加载成功。

对业务交互按应用自身需求验证，使用已有测试或适当的浏览器检查。测试数据、真实资源访问和写入遵循当前授权；仅有本地或模拟证据时，明确列出尚未验证的云端行为。

## 整理交付物

需要交给其他人、发布仓库或部署 Agent 时，阅读 [成品交付与验收](references/handoff.md)，按接收方已有格式提供成品及部署说明。没有既定格式时，用简短清单记录入口、基址、构建来源、运行依赖、资源配置和验证结果即可，不发明强制的通用清单协议。

交付物包含运行所需内容；密钥通过目标环境配置，保留配置名称与用途说明。源码仍在来源项目维护，接收方无需复制整个创作工作区。

最终说明：交付位置、目标路径、部署方式、已经验证的场景，以及仍需配置或验证的资源。区分构建通过、本地预览通过、平台部署通过与正式域名验收。

本技能的默认完成点是可交付成品及说明。Git 推送、云端部署、DNS 修改等操作沿用用户另行给定的授权范围；加载本技能本身不授予这些操作权限。

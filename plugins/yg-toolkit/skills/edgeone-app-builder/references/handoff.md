# 成品交付与验收

在需要把应用交给其他人、聚合发布仓库或部署 Agent 时阅读。优先使用接收方已有清单与目录规范；本文定义需要说明的信息，不强制统一文件名、JSON 结构、仓库目录或发布分支。

## 交付说明

| 信息 | 内容 |
| --- | --- |
| 应用与来源 | 应用标识、展示标题、版本或来源提交，成品位置 |
| 访问位置 | 目标基址、入口、路由方式；如需历史版，记录对应路径 |
| 构建方法 | 运行环境、依赖安装方式、实际构建命令、构建输出目录 |
| 部署组成 | 静态成品、平台函数、框架运行产物或外部服务，各自如何接入 |
| 所需配置 | 环境变量名称、是否秘密值、资源绑定与必要部署配置；不填写密钥明文 |
| 验证证据 | 实际执行的检查及结果、验证路径、尚未验证的能力 |

纯静态应用无需虚构服务端依赖或存储配置。存在接口、持久化、附件、计划任务等能力时，按应用实际情况补充部署说明；所需的初始化或迁移单独列出，不混入静态组装操作。

版本保留、数据共享和交互行为按当前需求或应用代码说明，发布底座只组织部署；不要为交付自动将历史版变为只读或更换其业务接口。

## 建议的成品组织

接收方没有既定格式时，可采用类似结构；各目录只在应用实际需要时出现：

```text
delivery/
  deployment.md
  static/
  runtime/
  config/
```

这是便于移交的文件包，不是 EdgeOne 可直接部署的固定目录规范。`static/` 存放已构建资源，`runtime/` 存放适配后的运行产物，`config/` 存放非秘密配置片段；部署时仍按已选平台方式组织入口与输出。接收方允许源码构建时，遵循其既有流程，不额外复制无关开发文件。

交付文件包应能定位构建来源，更新时明确替换范围。源码、开发依赖、日志、真实业务数据与成品分开保管；服务端运行所需依赖按打包方式保留。环境变量名可以进入说明，实际秘密值通过目标环境设置。

## 以实际访问结果验收

按应用包含的能力选择验证项，普通静态页面不需要人为增加接口、登录或数据库场景。

| 能力 | 观察结果 |
| --- | --- |
| 页面与子路径 | 在目标基址打开入口、直接访问深链并刷新，页面和导航正确 |
| 静态资源 | JS、CSS、图片、字体与懒加载资源返回预期内容；缺失文件不被错误回退成 HTML |
| 服务端与接口 | 触发真实的目标运行入口，响应状态与内容符合应用自己的设计 |
| 持久化 | 在获准的测试环境验证实际保存与读取，标明使用的资源和数据环境 |
| 附件 | 文件链接可访问并得到预期文件，位置与当前版或历史版一致 |
| 共站部署 | 应用路径、全站配置与共享状态不会意外改变其他应用 |
| 保留版 | 在需要保留时，版本路径、资源和应用原有行为正确 |

已有自动化检查、真实浏览器、平台本地开发工具或授权测试部署都可作为证据。选用能观察实际目标行为的方式；单纯的 HTTP 200、打包成功或开发环境正常不能覆盖所有验收项。

## 完成报告

给接收方交付成品位置与配置说明，区分以下状态：

- 构建通过：明确构建命令和产物。
- 本地预览通过：明确预览基址、已验证场景与不包含的线上能力。
- 平台测试部署通过：仅在有实际部署结果时报告，注明环境。
- 正式域名验收通过：仅在授权发布并检查正式域名后报告。

云端资源、环境变量或外部服务尚未配置时，报告“成品已生成，相关能力待接入验证”，不假称完整部署成功。用户只要求构建和移交时，完成交付即可，不自行推送、创建云项目或发布。

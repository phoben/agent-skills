# 约格内部平台交付

仅在目标为 `edgeone.yugasoft.cn` 或用户明确指定约格内部应用平台时使用。本指引约定该平台的接收方式；其他 EdgeOne Pages／Makers 项目仍按其自身运行方式交付，函数和 SSR 能力不受本指引定义。

## 成品范围

在来源工作区完成制作和构建，交付最终静态网页 ZIP。平台不会安装依赖、执行构建或启动后端，ZIP 内应是 HTML、JS、CSS、图片、字体及按需下载的 PDF、PPT 等附件。

接手已有项目时保留其技术栈、UI、样式、目录与业务功能。若应用需要 SSR、后端函数或其他运行程序，说明具体能力缺口，再评估静态导出或外部服务接入；不要删除功能后声称已经适配。静态导出的 `_next/` 等资源可以交付，不能把服务端 `.next/` 输出当成静态成品。

## 包内容与预算

推荐 ZIP 根直接放 `index.html`，只打包构建结果。交付说明、旧 `app.json`、源码、依赖清单与目录、`.env`、保密凭证、数据库备份及未经授权或超出平台内部共享范围的数据、后端函数和可执行文件留在包外。不要把未脱敏个人答卷或敏感身份资料用作演示数据。ZIP 不得有逃逸路径、链接、重复或大小写冲突的文件。

当前默认接收预算：ZIP 8 MiB、单文件 4 MiB、解压总量 48 MiB、250 个 ZIP 条目（包括目录条目）。附件同样计入。它们属于本平台预算，不是 EdgeOne 官方通用硬限；实际以上传界面和服务端校验为准，部分值可由平台配置调整。超限先报告大资源及可选处理，不擅自丢弃内容或增加收费资源。

ZIP 根可选提供 `edgeone-app.json`，例如：

```json
{
  "runtime": "static",
  "entry": "index.html",
  "portable": true
}
```

当前支持的说明字段如下，不要求来源项目增加其他字段，也不另造 Schema：

- `runtime`：提供时必须是 `static`。
- `entry`：存在于包内的 HTML 相对路径；推荐根目录入口。
- `portable`：默认 `true`，声明成品能随路径迁移，并不自动修复硬编码。设为 `false` 时不能直接改路径，需重新适配。
- `assetAliases`：可选对象，将已确认的根资源引用映射到包内文件。不能用它代理业务 API。
- `normalizeServiceWorker`：默认 `true`，用于已有注册检测的兼容处理，不提供离线能力。

该管理文件不公开，也不能写秘密。展示名称、路径和成员通过管理页面设置，不要求塞入 ZIP 清单；原仓库 `app.json` 属于旧静态接收流程，不能充当此上传清单。

## 路径与浏览器兼容

展示名称可用中文，路径建议简短易懂，例如 `aoy-brief`。最终路径由接收方确认，使用小写英文、数字和内部连字符，1–63 字符，不以连字符开头或结尾，且不能重名或占用平台保留路径。版本在包外说明中记录，不堆入稳定路径。

平台允许修改路径，成功后旧链接失效。成品应使用相对资源或经验证的可移植基址，不把首次 slug、`/assets`、`/api` 等根路径写死为专属地址。平台只有限适配已确认的包内 HTML/CSS 资源，不会重写所有 JavaScript。`portable: true` 不能代替换路径验证。

内容在不授予同源权限的沙箱中运行。新建项目可优先考虑 Hash 路由，降低深链和导航适配成本；已有 History 路由先定位不兼容场景，不擅自替换 Router 或重构框架。

不要依赖平台同源的 `localStorage`、Cookie、Service Worker 或离线能力。现有项目若依赖它们，说明具体操作会怎样失败、数据是否丢失，再完成必要适配。不得用内存保存冒充持久保存。普通本地静态服务器无法证明沙箱内的模块、导航、存储、下载和外部请求兼容。

## 业务接口与数据

平台登录保护访问入口，应用不会收到管理 Cookie、CSRF 凭证或钉钉 Token。不要尝试调用平台管理接口或假设平台登录能替代业务鉴权。

真实问卷、表单及其他业务的接口、持久保存、导出和访问权限由来源项目实现。针对实际沙箱请求验证外部服务鉴权与 CORS，不能为通过演示公开敏感接口，也不能把服务端密钥编进网页。需要 KV 等资源时由来源项目的服务端接入，不从托管网页直接获取平台绑定凭证。

## 验证与交付

1. 执行来源项目现有构建及相关检查，检查最终 ZIP 的入口、资源、预算和敏感文件。
2. 验证目标子路径、另一条可用路径、导航、刷新、模块及附件。对存储、离线能力和外部数据操作逐项说明结果；尚未在实际平台验证的项目明确列为待验收。
3. 提供 ZIP 和包外说明：展示名称、建议路径、目标已有应用（若更新）、来源提交或摘要、成品版本、变更、外部服务、已验证场景及限制。
4. 用户在 `/admin/` 上传或更新，等待真实部署状态。排队、处理中、失败或待核对不等于已上线；成功后再验实际链接和业务操作。本技能默认交付成品，不自行推送或发布。

管理 API 与私有 Blob 是在线应用及版本的权威来源。旧 `receive_zip.py`、本地 `apps/`、`dist/` 或 `main` 的静态成品变更不会自动替换在线托管数据；`main` 用于发布平台程序。

平台默认只保留当前成功版本，保留数量可配置。需要固定分享旧版时，可另发带版本标识的归档应用，并说明其接口和数据行为；不承诺所有历史永久保留，不把网页回退当成数据回退。

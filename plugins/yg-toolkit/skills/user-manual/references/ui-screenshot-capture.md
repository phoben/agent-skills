# 真实界面截图就绪协议

在手册任务需要捕获真实 UI 时阅读本文件。目标是取得已经完成业务加载、可供最终用户识别和操作的界面证据，而不是仅证明页面外壳已经打开。

## 不可变边界

- 被检查项目的应用代码严格只读。不得新增或修改源码、测试、夹具、配置、依赖、锁文件、构建脚本、样式或页面状态标记，也不得为截图要求项目提供新的 `data-*`、测试 ID 或 ready 标志。
- 优先复用已经可用的运行环境、账号、测试数据和浏览器能力。不得仅为截图安装依赖或改变项目启动方式。
- 手册文件、手册图片和 `.repo-user-manual/` 元数据仍可按任务范围写入。浏览器追踪、失败截图、日志等诊断材料写到仓库外或临时目录，不得作为正式手册素材。
- 只执行可安全观察的操作。涉及不可逆、财务、库存、权限、删除或外部消息的操作，遵循主技能的安全边界，不得为了取得截图而提交。

## 选择截图工具

根据当前项目和环境选择能够观察最多就绪信号的现有工具，不固定技术栈：

1. 优先使用能够同时观察 DOM、可访问性树、URL、网络响应和元素状态的浏览器自动化能力，例如项目已有且可直接运行的 E2E 驱动，或当前环境提供的浏览器自动化工具。
2. 如果项目已有安全、适用的 E2E 用例，可以只读复用其导航和定位信息；不得编辑用例、配置或快照基线来适配手册截图。
3. 对原生应用、WebView 或无法取得 DOM 的页面，使用当前环境已有的窗口或屏幕自动化工具，通过可见加载标志、OCR、区域图像变化和连续画面稳定性判断。
4. 多种工具都可用时，选择能直接验证业务终态且副作用最小的方案。单纯屏幕等待是 DOM 或可访问性状态不可用时的降级方案。

工具能够完成截图不等于页面已就绪；每张截图都必须单独通过下面的就绪门禁。

## 截图就绪门禁

按页面实际结构选择信号，不要求所有项目使用相同选择器。至少验证以下五层，任一层未通过都不得保存为正式素材。

### 1. 页面身份正确

确认当前 URL、窗口标题、可见页面标题、选中菜单、面包屑或主要对话框与目标步骤一致。角色敏感页面还必须确认当前登录角色，并通过该角色实际可见的菜单进入目标页面。

### 2. 目标区域可见

确认截图所需的表格、表单、详情、图表、弹窗或工作区已出现在视口中，尺寸非零，且没有被遮罩、登录页、错误页或无关弹窗覆盖。不要把导航栏或空白页面外壳当作目标内容已加载。

### 3. 瞬态加载已结束

检查目标区域及其必要的上级容器，确认可见的加载文字、旋转图标、骨架屏、进度条、占位卡片和半透明遮罩已经消失。加载元素可能一直留在 DOM 中但处于隐藏状态，因此判断可见状态，而不是只判断节点是否存在。

页面级 `load`、`DOMContentLoaded` 或网络空闲只能作为辅助信号。它们不能单独证明局部表格、级联请求、懒加载组件或图表已经渲染完成。

### 4. 业务内容进入明确终态

对截图中的每个主要异步区域，确认已经出现一种可解释的终态：

- 列表或表格：表头和真实数据行已显示，或者明确的空数据提示已显示；空白表体不是终态。
- 详情或表单：关键标签及对应值已显示，值不是骨架、空占位符或持续变化中的默认值。
- 图表或仪表盘：标题、图例、坐标、数据标记或明确空状态已完成渲染；仅有空的 `canvas`、`svg` 或容器不算完成。
- 图片或媒体：所需资源已成功显示，不是破图、占位图或仍在加载的缩略图。
- 分页、统计卡和关联面板：凡是会影响截图含义的区域，都必须显示数据或明确空状态。

若工具能够观察网络，可在触发导航或查询动作之前监听相关请求，并确认响应成功；随后仍须验证 DOM 或可见业务结果。不要只因某个请求成功就判定截图就绪，也不要依赖全局网络空闲，因为轮询、长连接和无关后台请求可能让它永远不成立或过早成立。

### 5. 内容达到短时稳定

在前四层通过后，对目标区域进行连续观察。至少两次相邻采样中的关键文本、数据行数、可见加载状态和区域尺寸应保持一致；存在图表、图片或复杂布局时，同时比较目标区域画面。采样间隔用于确认稳定性，不得用一个固定长延时替代前四层判断。

如果工具支持，应在截图时禁用动画或等待过渡结束，并固定视口、缩放、滚动位置和目标区域。仅在提示消息不是截图主体时等待其自然消失；不得通过修改应用样式或代码隐藏真实产品内容。

## 无 DOM 或网络信息时的降级判断

使用纯屏幕或窗口工具时，按同样的业务语义执行门禁：

1. 用可见标题、菜单高亮或窗口内容确认页面身份。
2. 观察加载文案、旋转图标、骨架块和遮罩已经消失。
3. 通过 OCR 或人工视觉检查确认数据、明确空状态或关键详情值已经出现。
4. 对目标区域连续取得临时画面；只有在连续画面基本一致且不再出现布局跳动后才正式截图。
5. 无法区分“仍在加载”和“真实为空”时，判定为未就绪，不得猜测。

## 超时、重试与失败关闭

- 根据项目已有超时、页面复杂度和当前环境设定有界等待；普通页面可从 30 秒起步，已知慢页面可以合理延长，但不得无限等待。
- 超时后先记录未通过的门禁及可见现象。只有当导航和刷新是安全、幂等且不会改变业务数据时，才允许重新进入或刷新一次后重试。
- 重试后仍无法证明就绪时，停止该截图。可以把诊断截图和日志保存到临时目录，但不得移动到手册图片目录，也不得在手册中引用。
- 在对应步骤使用统一的“待补充真实界面截图”标记，并在交付说明中列出页面、角色、未通过的门禁以及环境限制。

## 截图质量复核

正式写入手册图片目录前逐张确认：

- 页面和角色与手册步骤一致；
- 所有影响含义的异步区域均处于数据、空状态或完成状态；
- 没有意外的加载、骨架、遮罩、动画中间帧、错误提示或半渲染内容；
- 关键操作位置清晰，裁剪保留足够定位上下文；
- 不包含开发者工具、内部标识、密钥、无关账号信息或其他敏感数据；
- 图片路径、替代文本和相邻操作步骤一致。

只有全部通过的截图才是手册证据。任何无法确认是否完整加载的画面都按失败处理，而不是按“可能可用”处理。

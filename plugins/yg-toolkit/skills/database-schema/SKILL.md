# 数据库结构快照

使用脚本完成确定性提取，Agent 负责选择目标、保护秘密、处理依赖并验收结果。此 Skill 只导出数据库逻辑结构，不导出表数据、用户、角色、授权、密码、任务调度或服务器级配置。

## 固定项目目录

所有运行数据必须位于当前项目根目录的 `.database-schema/`，不得改写为 Skill 安装目录，也不得向用户提供自定义路径参数。Git 项目使用 Git 顶层目录；非 Git 项目使用当前工作目录。

首次配置或需要新增连接时，阅读 [connections.md](references/connections.md)，然后执行：

```bash
python <skill目录>/scripts/export_schema.py --init
```

初始化不会覆盖已有配置。连接配置只登记环境变量名；禁止写入明文密码。Agent 不得要求用户把密码、完整含密钥 URL 或 Token 发送到聊天中。

## 解析目标

连接别名与数据库名是两个独立参数：

- 第一个参数是 `connections.json` 中的连接别名，只描述服务器、认证和连接安全策略。
- 第二个参数是本次要导出的真实数据库名，不写入连接配置，也不放入环境变量。
- 用户显式提供时直接使用，例如 `$database-schema yuga res-v4`。
- 用户未显式提供时，Agent 可从当前任务上下文判断；任一参数无法唯一确定时，询问连接别名或数据库名。
- 没有连接配置时，引导用户初始化并配置，不猜测连接信息。

连接别名必须精确匹配；不要把数据库名或模糊子串当作连接选择结果。

## 安全预检

执行前检查：

1. `connections.json` 不含 `password`、`pwd`、`secret`、`token` 等明文秘密字段。
2. 连接引用的变量可从进程环境、项目根 `.env.local` 或 `.env` 解析。
3. 秘密来自 dotenv 时，该文件未被 Git 跟踪且已被 Git 忽略。
4. 日志、错误、命令参数和最终清单不包含秘密值。
5. 连接账户具备读取元数据和对象定义的权限，但不要求写入数据库。

脚本会强制关键安全检查。Agent 仍应在运行前检查项目 `.gitignore`，并在发现泄露风险时先停止和说明影响。

## 执行提取

```bash
python <skill目录>/scripts/export_schema.py <连接别名> <数据库名>
```

脚本按对象生成一个 SQL 文件，并保存到：

```text
.database-schema/schemas/<连接别名>/<数据库名>/<对象类型>/<对象>.sql
```

公共类型包括 `schema`、`table`、`view`、`materialized_view`、`function`、`procedure`、`trigger`、`sequence` 和 `type`；数据库特有对象使用明确目录，例如 MySQL 的 `event`、PostgreSQL 的 `extension`、SQL Server 的 `synonym`。表文件应包含列、约束和索引；触发器必须独立存放。

每个成功快照必须包含 `manifest.json`，记录连接别名、数据库类型、数据库名、导出时间、对象与相对文件，不得包含主机密码、连接 URL 或用户名。输出文件名必须可跨平台使用，并通过稳定哈希避免同名或重载冲突。

## 原子覆盖

每个数据库先写入 `.database-schema/.tmp/`。只有对象清单和全部 DDL 均成功后，才能替换对应旧快照：

- 单库失败：删除临时结果，保留上一次完整快照。
- 替换异常：优先恢复备份目录，不能留下半套正式快照。

不得为了让命令成功而跳过无权读取或无法生成 DDL 的对象。应报告缺失权限或工具能力。

## 缺少 CLI 或导出异常

读取 [cli-tools.md](references/cli-tools.md)，识别当前数据库需要的工具。优先使用已安装的官方 CLI；安装工具或拉取容器镜像前必须说明影响并获得用户确认。

备用顺序：

1. 修复或安装官方 CLI/模块；
2. 在用户批准后评估官方容器，并确认网络地址在容器内有效；
3. 仍不可用时停止，不得用不完整或推测生成的 DDL 冒充快照。

错误输出先按已解析秘密值脱敏，再呈现给用户。最多进行一次安全、幂等的连接重试；认证失败、权限不足和确定性语法错误不要自动反复尝试。

### SQL Server TLS 决策门

SQL Server 默认使用 `encrypt=true` 与 `trustServerCertificate=false`。当运行报告返回 `SQLSERVER_TLS_CERTIFICATE_UNTRUSTED` 时，停止自动重试并说明：传输加密已启用，但服务器证书链无法验证。

- 正式、生产或公网连接：推荐由数据库管理员配置可信证书，或在本机安装正确的 CA 链，然后保持严格校验重试。
- 本地、开发、受控内网或临时诊断：只有用户明确接受服务器身份无法验证的风险后，才把目标连接设为 `trustServerCertificate=true`；保持 `encrypt=true`，仅重试一次。批准时确认范围：单次导出应在完成或失败后恢复原配置；连接级批准才保留该设置。
- 不把 `encrypt=false` 作为证书异常的自动备用方案。

使用证书信任模式成功后，最终结果必须说明“传输已加密，但服务器身份未校验”，并说明配置已恢复严格校验或将持续保留，不能让用户猜测批准范围。

## 验收

完成后至少验证：

- 命令退出码为零。
- 正式目录中存在 `manifest.json`，状态为 `complete`。
- manifest 对象数与各分类 SQL 文件数一致，所有列出的文件存在且非空。
- 临时目录和替换备份已清理。
- 连接配置、快照、manifest、运行报告和终端输出均未出现秘密值。
- 重复导出正确替换旧目录，不保留已删除对象的陈旧文件。
- SQL Server manifest 的 `connectionSecurity` 与实际加密、证书校验状态一致；若未校验服务器身份，最终结果明确披露。

明确区分脚本静态测试、CLI 可用性、数据库连接成功和真实结构完整性。没有连接真实数据库时，只能报告本地逻辑与模拟测试通过。

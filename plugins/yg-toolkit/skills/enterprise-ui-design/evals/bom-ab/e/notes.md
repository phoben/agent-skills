# 方向三：变更单覆盖在基线之上

这是经独立概念发散后定向实现的原型，并非盲测首稿。它把 V3 的完整 BOM 保持为稳定、可扫读的主表；进入编辑后，右侧只收集本次尚未保存的覆盖项。用户可以逐项撤销，并在保存前同屏核对完整结果和两项明确的变更意图。保存后，覆盖写入 V3 基线；只有此时才能复制为 V4 草稿。

## 可走查的业务路径

1. 初始页已定位 `CP-1008`，左侧同时可辨认 `V3 生效` 和 `V2 历史`，主表完整显示三个子件、来源、用量和规格。
2. 点击“发起本次变更”，对外壳执行“调整用量”、对缓冲垫片执行“调整规格”；右侧生成两项差异。主控板规格没有修改入口，临时垫片的“虚拟件（固定）”在变更记录中保留。切换 SKU 或版本时，未保存的变更会提示放弃后果；关闭页面也会触发浏览器离开保护。
3. 点击“核对完整结果并保存”，弹层同时列出三条合成后的子件结果与两项本次意图。确认后，V3 的主表成为新基线。
4. 点击“复制为 V4 草稿”，确认复制对象和 V3 保持生效的后果；完成后切换至 V4，查看继承的三条子件及修改值。

## 原型边界

全部数据都只存在浏览器内存中。没有真实权限、后端整树保存、并发冲突、审批或发布流程；大规模变更单的分组与分页也仅在说明层面保留，未作为本次三项 BOM 的模拟交互实现。

# 标准 BOM 维护原型说明

## 设计依据

- 角色假设：PC 管理后台的 BOM 维护人员，在成品 SKU 下查看版本并维护当前生效版本的完整子件清单。
- 已核对事实：成品 SKU 固定；保存为整树保存；已有 SKU 的规格在 BOM 内只读；临时物料规格可编辑且必须为虚拟件；仅当前生效版本可复制为新草稿。
- 页面入口：通过成品 SKU 和生效状态查询，在左侧结果中定位版本；右侧始终保持当前版本身份、状态、保存范围和完整子件清单。

## 布局取舍

候选一为常见的“查询表格 + 编辑弹窗”：能承继后台列表习惯，但在保存前需要从弹窗回看清单或在弹窗内滚动，版本身份与整树保存范围较难同时保持可见。

候选二为本稿采用的“版本结果区 + 同页对象工作区”：左侧让同一成品的 V3、V2 和复制后的 V4 连续可比；右侧将当前对象、整树保存范围和全量子件表放在一个工作区。用户编辑用量或临时规格后，未保存提示直接指向同一张完整清单；复制前的对象与后果在确认框中说明。

## 原型边界

- 全部数据为浏览器内存模拟数据，保存、复制和还原不会调用真实接口或写入 ERP。
- 未实现真实账号权限、SKU 选择器、临时物料建档字段校验、发布审批、服务端冲突、分页和大数据性能策略。
- 浏览器的离开提醒仅在本页存在未保存修改时触发，实际浏览器行为会受浏览器设置影响。

## 共同任务本地走查记录

在本地文件直接打开后，进行点击与输入走查：

1. 用 `CP-1008` 查询，左侧可见生效 V3 与历史 V2；选择 V3 后可见 3 个子件、物料来源、用量和规格。
2. 在 V3 将外壳用量输入 `2.5`，将缓冲垫片规格输入“厚度 1.2mm”；主控板和外壳规格呈只读标记，缓冲垫片显示“临时物料、必需、虚拟件”；保存前出现未保存提示与完整子件清单；确认模拟保存后显示结果提示。切换版本或关闭页面时存在未保存修改会出现恢复提示。
3. 从 V3 点击“复制为新版本”，确认框展示复制对象、V4 草稿及 V3 保持生效的后果；确认后左侧出现 V4 草稿，打开后可见 3 个子件及已编辑的 `2.5` 和“厚度 1.2mm”。

关键控件位于主工作区或固定底部操作栏；子件表在较矮视口以内嵌滚动查看，未保存提示可定位回完整清单。`1440×900` 和 `1280×720` 的正式截图与评测记录留给统一评测环节。

# 第三轮 A/B 结果：标准 BOM 维护

## 结论

在这一轮真实项目业务场景、同一模型能力和同一任务简报下，两版均能完成三条任务，主骨架仍是左侧定位、右侧子件清单。**本轮未证明技能带来布局优势。**独立盲审判定 B 整体更好，主要依据是保存确认、未保存恢复与版本状态；用户实际看图后更偏好 A 的空间比例和卡片排布。应把盲审结果限定在流程完整性，不能据此宣称 B 的布局更好。

这是一例定性对比。A/B 的设计者为独立代理，分别只读共同 [业务简报](brief.md)，B 另读技能；[评测规程](rubric.md)在看首稿前确定。首稿冻结后，独立评测者只看简报、规程、原型和截图，不看技能与设计说明，其 [盲审结论](blind-review.md)为 B 更好。评测者一人、一个页面、三条脚本，不应推导跨项目效果百分比。

## 首稿对比

| 观察 | A：未用技能 | B：使用技能 |
| --- | --- | --- |
| 页面骨架 | 左侧按成品 SKU 分组，右侧用版本标签切换完整子件表 | 左侧每条记录为一个成品版本，右侧显示当前版本身份、子件表和固定操作区 |
| 定位版本 | 同一成品卡片内可识别 V3 生效与 V2 历史；紧凑 | V3、V2、复制后的 V4 分别作为可点击对象，版本与状态更直接 |
| 修改与核对 | 三行全量清单同屏；保存 V3 直接完成，步骤少 | 同屏修改；未保存提示指向三行，保存前再确认对象和整树范围，多一次操作 |
| 未保存切换 | 浏览器原生确认，取消可保留修改 | 页面内对话框明确“留在当前版本”与“放弃修改并切换” |
| 复制后 | V4 草稿与 V3 生效可见、修改值保留；V4 仍有编辑输入但无保存入口，状态含混 | V4、V3、V2 独立可见，修改值保留；V4 标为本原型只读，动作禁用 |
| 1280×720 | 三行、完整宽表与保存动作首屏可见，无横向滚动 | 三行与固定保存栏首屏可见，无横向滚动；页面有轻微纵向溢出 |

两版浏览器实测均完成：定位 `CP-1008 V3` 与 `V2`；将外壳用量改为 `2.5`、临时垫片规格改为「厚度 1.2mm」并模拟保存；从 V3 复制 V4 草稿，确认三条子件和改值保留。A 修改并保存需两次输入加一次保存动作；B 另需一次保存确认。复制均需一次发起和一次确认。两版在 `1440×900` 与 `1280×720` 均无横向溢出或浏览器脚本错误。

## 用户看图后的修正

用户指出 A 左栏宽度更合理，B 左栏抢占右侧空间；A 卡片以标题、描述、分割线和标签建立层级，B 的宽卡片更稀疏；A 的“必需”状态表现仍有局部细节不足。亲自复看 `1280×720` 编辑截图后，这些观察有直接证据：A 左栏约 310px、右主区约 904px；B 左栏约 419px、右主区约 795px。到 `1440×900`，B 的左栏进一步扩至约 544px，右表格约 829px，而 A 左栏仍约 310px、右表格约 1064px。B 的侧栏宽度随视口增加，却未承载相应更多内容。旧盲审量测了表格宽度，却没有把空间分配作为独立结论，这是评测缺陷。

## 布局能力的实际差异

- **可证实的流程增益**：B 将「成品 + 版本 + 状态」组合成左侧定位单位，右侧始终呈现整树保存范围；版本复制后仍可直接对照 V3 生效与 V4 草稿。其未保存与确认状态更完整，但不能抵消较差的空间比例。
- **A 的长处**：右侧表格更宽，来源、必需、虚拟件分列明确；卡片的标题、名称、分隔和状态更有层次，在本轮三行数据里编辑与保存也更快。它在视觉布局上是更强的基线。A 的“必需”高亮方式仍可按项目状态样式优化。
- **尚无证据的部分**：两个方案的主要空间结构相同；没有真实用户计时、更多数据行、权限差异或服务端运行证据，不能宣称 B 大幅提高效率，也不能称其布局最优。
- **测试偏差**：B 初始搜索框预填 `CP-1008`，使“从多条成品定位”的难度变低；A 初始展示 `CP-1008` 和 `CP-1020`。版本信息的呈现差异仍可比较，但任务 1 的查找耗时不能公平量化。

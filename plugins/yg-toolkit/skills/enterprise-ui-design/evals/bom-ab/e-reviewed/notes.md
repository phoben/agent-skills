# E 版视觉修订：完整基线与变更单

## 修订目标

保留“完整 BOM 基线 + 可撤销本次变更 + 保存前核对完整结果”的业务模型，消除原 E 版在 1280 × 720 编辑态中三栏互相抢宽、主表被压缩、右侧操作落在首屏之外的问题。

## 布局决策

页面使用左侧对象列表与右侧主工作区两栏。完整 BOM 始终占据主工作区的最大宽度；开始编辑后，变更单作为同一工作区内的下方核对区出现，两项变更横向排列。这样用户按“修改完整基线 → 查看本次差异 → 保存前核对”的自然顺序向下工作，避免把变更单和主表同时压成窄列。

720 高度的编辑态会收起重复的版本导航，并压缩仅用于定位的顶部间距；对象、版本状态、完整 BOM、两项变更与保存操作仍保留在同屏。这里的代价是编辑时不同时展示版本切换控件，但当前版本状态仍在标题下可见，且编辑中切换版本本身不是主任务。

保存后保留简化的变更单区域，显示“V3 已保存为新的完整基线”，并露出“复制为 V4 草稿”操作，避免保存成功后复制入口被折叠隐藏。

## 交互验证

- 通过浏览器实际点击：发起本次变更 → 调整用量 → 调整规格；1280 编辑截图已记录两项覆盖及保存按钮。
- 主控代理随后使用本机 Playwright/Chrome 重新执行 `发起本次变更 → 调整用量 → 调整规格 → 核对完整结果并保存 → 确认保存 V3 → 复制为 V4 草稿 → 确认复制`。浏览器显示保存后复制按钮可见且可用；复制后为 `草稿版本 V4`，完整 BOM 为 3 行。1280×720 的最终页面文档尺寸等于视口，无横向或纵向溢出。另重新抓取最终 `1440×900` 编辑态，也无文档溢出。
- 另把用量改成 `3.5`、规格改成 `厚度 1.5mm`，浏览器确认保存弹层动态展示两项实际新旧值，V4 草稿继承这两个数值。修正了原型中确认文案写死默认示例值的问题。

## 仍然存在的取舍

变更单放在表格下方意味着用户需要在两个区域间做短距离垂直扫视；换来的是主表保持完整横向扫描能力。对于超过数十项变更的场景，应将下方区域改为可筛选的变更清单或独立复核步骤，不能无限堆叠卡片。

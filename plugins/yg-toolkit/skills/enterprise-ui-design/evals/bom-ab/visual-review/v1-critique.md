# BOM 维护页视觉评审（仅基于截图）

## 结论

排序：**Y 第一，X 第二**。

Y 更接近成熟企业后台：主操作区的层级稳定，表格像可核对的业务清单，1280 宽度下仍保持完整、规整的横向扫读。X 的信息组织较轻盈，三栏结构也容易理解，但其大面积空白与弱化的表格边界使页面显得像尚未填充完的原型，信息承载感不足。

## 最重要的三个画面差距及任务影响

1. **表格的业务密度与行列锚点**

   Y 用清晰的列线、稳定行高和左中右对齐，将三条子件组织成可快速比对的清单；规格和用量的输入框也落在固定列中。X 表头与行分隔较轻，缺少纵向锚点，且中央表区之外有大量空白。维护人员核对三条子件时，Y 更容易沿列复核“子件—用量—单位—规格”，X 更依赖逐行停留，长字段与状态标签会打断横向比较。

2. **页面空间比例**

   X 在两种宽度下都让主卡、左版本卡和右复核卡延伸到接近页面底部，而实际内容只占上半部；空白像未完成的画布，削弱了保存前维护页应有的紧凑感。Y 同样有下方留白，但详情卡的内容、底栏和左清单共同形成完整工作单元，空白被压到工作区外。对于连续编辑用量和临时规格的操作，Y 的视线停留范围更集中，X 会让内容显得稀薄、操作重心偏上。

3. **视觉层级的连贯性**

   X 将版本、编辑表和提交前核对拆为三张并列卡片，卡片外观一致，主次关系主要靠中央宽度区分；深色顶栏也与页面内柔和浅色体系略显断裂。Y 从当前 SKU、版本页签、提示带、明细表到保存栏按垂直顺序形成一条阅读路径，选中的 SKU 卡和当前版本再给予适度蓝色强调。成品 BOM 维护人员在编辑后回看状态时，Y 的视线可自然回到同一详情面板，X 则需要在中央表和右栏之间反复跳转。

## 画面层面的保留意见

Y 的筛选区域横跨整页却只放置少量控件，1440 宽度时显得宽松；表格网格与若干浅色底块也略有传统后台的“框感”。X 的圆角卡片、标签和较少的网格线更轻快，若收紧卡片高度、提高次要文字对比度，并强化表格列关系，具有更现代的视觉基础。

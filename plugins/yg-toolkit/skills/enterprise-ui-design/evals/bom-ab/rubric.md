# 第三轮评测规程（首稿冻结前确定）

## 比较边界

唯一干预是 B 设计者阅读并执行 `enterprise-ui-design` 技能；A 使用常规设计能力。两者使用相同模型、共同业务简报、模拟数据与交付格式，不互读对方产物。首稿比较只看 `a/index.html` 与 `b/index.html`；审查修订另记，不计入首稿布局收益。

本轮只有一个页面、一名评测者和本地模拟原型，不得据此推断跨项目平均提升或最优布局。

## 共同操作

从页面初始状态分别执行简报三条任务。每条任务重新载入页面，记录完成结果、所需点击或键盘操作、跨视图切换、关键对象是否持续可见、错误与恢复。用相同 1440×900 和 1280×720 视口截取初始和编辑态；不通过放大缩小页面改善任一方案。

## 布局观察维度

| 维度 | 观察证据 |
| --- | --- |
| 对象定位 | 能否区分成品、版本、生效状态和子件；定位目标的步骤及重复查找 |
| 编辑连续性 | 改用量、改临时规格、核对全量子件时是否丢失上下文；需要几次视图切换 |
| 信息密度 | 1440×900 与 1280×720 下关键列、核对范围、提交动作是否可见；横向滚动和遮挡 |
| 版本因果 | 复制对象、后果、V3 与 V4 状态是否清楚；复制后能否验证子件保留 |
| 状态恢复 | 未保存提示、提交反馈、无数据与无权限说明是否支持继续操作 |
| 系统一致性 | 是否沿用 B 端表格与中文术语、克制的动作层级；是否出现无业务依据的装饰 |

每个维度记录具体行为与截图，不以卡片数量、配色或“惊艳程度”代替任务效果。以用户的主观体验为最终补充判断；评测者不预设技能版优胜。

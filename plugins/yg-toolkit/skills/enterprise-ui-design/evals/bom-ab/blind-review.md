# 标准 BOM 维护：第三轮独立盲审

## 范围与方法

本审查仅读取共同简报、量表、`a/index.html`、`b/index.html` 及其各自交付截图；未读取两份 `notes.md`、技能说明、其他评测或既有结论，也未假定任一方案的设计来源。原型与目标 ERP 均未修改。

在本地 Chromium 中分别以 `1440×900`、`1280×720` 打开两份单文件原型。从初始状态执行共同任务；编辑后按简报顺序保存并复制。两案的浏览器控制台均未报告脚本错误。下文的“操作数”将一次字段填写、一次点击或一次确认各计为一次，不把阅读表格计入操作。

## 共同任务实测

| 任务 | A：路径、切换与结果 | B：路径、切换与结果 |
| --- | --- | --- |
| 1. 定位并核对 V3/V2 与子件 | 初始即选中 `CP-1008/V3`；左侧同一 SKU 卡内可见 `V3 生效`、`V2 历史`，右侧表同时给出 3 行来源、用量、规格。完成需 0 次操作、0 次视图切换。代价是版本是 SKU 卡内的标签，版本本身不是独立列表项。 | 初始查询为 `CP-1008`；左侧把 `V3 生效`、`V2 历史`列为两条独立记录，并在每条上显示 3 个子件。右侧表完整可见。完成需 0 次操作、0 次视图切换；成品、版本和状态的结合最直接。 |
| 2. 修改、核对、保存与防误离开 | 在表内填写外壳 `2.5`、垫片规格 `厚度 1.2mm`，看到已有 SKU 规格“只读”、临时物料“虚拟件=是”和全量 3 行；页脚显示未保存提示，点击“保存 V3”即完成模拟保存，共 3 次操作、0 次切换。尝试带未保存修改切到 V2 时触发浏览器原生确认；取消可留在 V3，但原生弹框与页面提示的可见性和文案难以由页面自身持续承载。保存没有再确认整树范围。 | 在表内作同样两次填写，编辑提示明确指向“以下全部 3 个子件”，固定页脚提示未保存；点击保存后出现确认框，重述 `CP-1008 V3`、整树 3 项、已有 SKU 规格只读及临时垫片仍为虚拟件，确认后成功，共 4 次操作、0 次切换。尝试切 V2 出现页面内对话框，明确给出“留在当前版本”和“放弃修改并切换”，取消后编辑值仍在。多一次确认换来更可审核的保存与恢复边界。 |
| 3. 从 V3 复制并核对 V4 | 保存后点击“复制为 V4 草稿”再确认（2 次操作、0 次切换）。对话框清楚说明复制对象、保留 3 个子件/临时资料/已保存修改、V3 保持生效且不发布审批。复制后 V4、V3、三行及改值都可见。问题是 V4 仍显示可编辑输入框，但保存和恢复按钮隐藏，草稿是否可编辑在交互上含混。 | 保存后点击“复制为新版本”再确认（2 次操作、0 次切换）。对话框说明对象、整树清单、V3 仍生效和 V4 草稿；复制后左侧按 `V4 草稿`、`V3 生效`、`V2 历史`分别列出，右侧显示 3 项及改值。V4 明确标为“草稿版本只读（本原型）”，复制按钮和保存按钮禁用，状态边界一致。 |

## 视口与信息密度

| 观察 | A | B |
| --- | --- | --- |
| 1440×900 | 表格、左右列表、版本标签、未保存状态和保存动作均不需滚动；表格容器宽 1064px，没有横向溢出。 | 全部关键列及保存固定栏可见；表格容器宽 829px，没有横向溢出。固定页脚位于 y=836–900。 |
| 1280×720 | 仍保持左右栏，3 行全表、状态与保存动作都在首屏；表格容器宽 904px，无横向溢出；保存按钮范围 y=632.5–669.5。 | 左右栏、3 行全表和固定保存栏仍可见；表格容器宽 795px，无横向溢出；固定页脚 y=656–720。页面有约 4px 的纵向溢出/滚动条，但未遮挡关键控件。 |

两案在本轮给定的三行数据和两种视口都没有横向滚动；因此不能把“有更多列时的横向取舍”外推为已验证。A 的 10 列并列使来源、规格、必需、虚拟件分列更显性；B 将必需和虚拟件合到“约束”，换得在较窄右侧详情区更稳定的列宽，并保留物料来源和锁定规格的识别。

## 量表观察

| 维度 | 判断 | 证据 |
| --- | --- | --- |
| 对象定位 | B 较好 | B 的左侧记录以“成品 + 版本 + 状态 + 子件数”为一个可点击对象；A 要从 SKU 卡内的版本标签辨认。 |
| 编辑连续性 | B 较好 | 两案均零切换完成编辑；B 的编辑提示、固定未保存栏、整树保存确认连续地保留核对语境。A 的即时保存更快，但少一层关键确认。 |
| 信息密度 | 各有优劣 | A 在宽屏把约束拆列，核对更逐项；B 在 1280 仍无横向滚动，且固定页脚始终给出提交入口。 |
| 版本因果 | B 较好 | 两案复制提示均合格；B 复制后的 V4/V3/V2 独立可见且草稿只读，A 的 V4 输入框和隐藏保存动作形成状态歧义。 |
| 状态恢复 | B 较好 | B 使用页面内留在当前版本/放弃修改二选一和还原动作；A 主要依赖浏览器原生 `confirm`，保存也没有范围确认。 |
| 系统一致性 | B 略好 | 两案均使用克制的表格与中文术语。B 的行级版本列表、状态标签和固定底部提交区更接近复杂后台的可审查操作模式；A 的整体更紧凑。 |

## 结论：B 更好

B 在三条共同任务均成功的前提下，把版本作为稳定可定位的业务对象，并将未保存编辑、整树保存、复制后的状态边界做成页面内可见且可恢复的流程。它为保存增加一次确认，牺牲一点速度，但符合“提交前核对完整子件清单”的业务风险。

A 的宽表逐列核对和紧凑路径有价值，且两个视口都可完成任务；建议其后续优先把未保存切换、整树保存确认迁入页面内，并消除 V4 的可编辑外观与不可保存行为之间的矛盾。B 则应修复 1280×720 的轻微纵向溢出，并在子件显著增多时复测固定页脚与表格滚动的遮挡关系。

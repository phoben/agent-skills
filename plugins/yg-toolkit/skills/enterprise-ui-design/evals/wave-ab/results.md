# 出库波次工作台第二轮 A/B 评测

## 为什么重测

第一轮收货原型的共同简报预先给出了参照、扫码、历史、清单和固定确认区，不能有效区分技能对布局的影响。本轮仅固定角色、业务规则、模拟数据、三条任务和企业后台约束，没有指定布局。两位独立代理使用相同模型能力；A 不读新技能，B 读新技能。两版均冻结首次原型，尚未把审查修订混入首稿对比。

## 首稿事实

| 观察 | [A 版](a/index.html) | [B 版](b/index.html) |
| --- | --- | --- |
| 主要布局 | 左侧候选来源表，右侧已选来源与下达动作；结果在页面上方呈现 | 左侧候选来源表，右侧固定核对、下达动作与结果；页面上方显示恢复条 |
| 设计决策记录 | 说明同屏选择、核对与恢复，但未列结构候选 | 明确比较“沿用列表与两层弹窗”及“单页双工作区”，选择后者并说明上下文优势 |
| 附加操作 | 要求先选仓库，选中后可逐条移除；提供草稿保存 | 默认模拟仓库；提供按单号或货主筛选、逐条移除及草稿保存 |
| 失败与恢复 | 原草稿保留；移除失败来源并加入替代来源后可下达 | 同样保留原草稿，失败说明位于核对区，调整后可下达 |
| 结果暂不确定 | 下达按钮禁用，先查询原操作结果 | 点击下达时阻止重复创建，页首要求先查询原操作结果 |

两版在本地浏览器均完成：选择两条来源合计 36、首次下达失败并保留原草稿、替换来源后成功下达 32、结果未明时先查询再继续。A 与 B 的主布局仍高度相似，说明第一轮的相似性不能完全归咎于共同简报；面对同一任务，通用设计代理也会选择合理的同屏主从结构。B 的显著增量是**明确比较布局候选和记录取舍**，不是首稿中的全新布局类型。相似性仍不能证明这种布局最优，用户对操作效率和视觉感受的判断尚未加入本轮。

## 首稿独立审查

[B 版审查记录](b/review.md)的结论是**阻断**：下达成功后页面仍显示可编辑草稿，再次触发下达也会得到成功反馈。审查还指出提交中防重复与候选重新校验缺少可验证状态，以及多个“移除”按钮没有对应单号的可访问名称。由此，三条预设脚本通过不等于 B 首稿可交付，也不能把审查尚未修复的质量记作技能首稿的收益。后续修订版与首稿分开存放、分开评价。

[B 审查修订版](b-reviewed/index.html)保留首稿布局，补上已下达只读态、提交中锁定、失败后的候选重新校验和明确的移除名称。[定向复核](b-reviewed/review.md)已用浏览器验证上述问题关闭。这个改进属于独立审查与修订闭环的收益，不能归因于技能首次生成的布局能力；模拟校验也不能替代真实服务端验证。

## 证据与限制

- [A 总览](a/overview.png)与 [B 总览](b/overview.png)在同一 1440×900 视口截取。原型均不连接后端；目标项目只读，真实主题、角色权限和大数据性能未验证。
- B 的设计理由和两种布局候选见 [B 设计记录](b/notes.md)。首次原型与后续审查需要分开评价，不能把审查修复算作首次布局设计效果。
- 本轮仍只有一个复杂业务场景、两份原型和代理操作验证；不能据此给技能设定跨项目的效果百分比，也不能宣称“最佳布局”。

# B 版首次原型说明

## 设计依据

- 角色是有查询、新建和更新权限的仓库计划员；从“出库波次”进入后，在同一仓库的直接出库单与装车单中组建波次。
- 已核对源码事实：现有页面有仓库筛选、候选选择、草稿创建、下达，以及操作结果查询/重试语义；创建过程当前由弹窗和候选弹窗承载。真实运行权限、主题和接口反馈尚未验证。
- 原型仅使用共同简报中的模拟数据，不连接服务端，也不写入库存。

## 操作摩擦与布局选择

现有弹窗式流程会在“候选选择 → 已选核对 → 下达结果 → 回到草稿调整”之间切换上下文。失败原因与原已选来源不在同一个稳定视域中，计划员容易忘记需要移除哪一条，也难以确认下一次下达的范围。

| 候选结构 | 完成组建与失败恢复时的表现 | 取舍 |
| --- | --- | --- |
| 沿用：波次列表页 + 创建弹窗 + 候选弹窗 | 继承现有组件与操作位置，实施成本低；每次挑选和核对都要在两层弹窗间返回，失败后需重新定位草稿。 | 适合字段少、无需连续调整的创建。无法直接解决本题的上下文丢失。 |
| 采用：单页双工作区，左侧候选表、右侧固定核对与结果区 | 选择立即反映在核对清单；删除、数量合计、失败原因和再次下达围绕同一草稿；仓库切换直接清空选择并提示。 | 需要新增一个工作台入口或将创建弹窗扩展为全屏工作区；在窄屏会改为上下排列。 |

选择第二种。它将高频的候选定位和低频但关键的结果恢复放进同一可见空间，减少回退步骤，并让下一次下达范围可被再次核对。

## 已实现交互与状态

- 选择华东成品仓后，可勾选候选、按单号或货主筛选、在右侧移除误选，并实时看到来源类型、单号、货主、计划量与合计。
- “仅存草稿”显示模拟草稿号和已选来源；切换仓库会清空选择，避免跨仓库保留。
- 同时选中 `CK-20260923-041` 与 `ZC-20260923-007` 下达时，显示库存不足、草稿保留、未产生部分预占/任务；移除装车单、选择 `CK-20260923-052` 后可再次下达成功。
- “模拟：下达结果暂不确定”显示页首恢复条；在查询原操作结果前，主下达动作会阻止再次创建；查询后明确原波次未创建且草稿可调整。
- 空仓库、无选择、成功、失败、暂不确定及草稿状态已覆盖。权限、真实冲突、服务端加载与性能为业务系统实施后的验证项。

## 三条任务脚本与自测记录

1. **组建波次**：保留默认仓库，勾选 `CK-20260923-041`、`ZC-20260923-007`；右侧显示两条、合计 36。点击任一“移除”仅删除对应来源。已静态与交互走查。
2. **失败恢复**：以上两条点击“创建并下达”，出现库存不足与草稿保留说明；移除 `ZC-20260923-007`，勾选 `CK-20260923-052`，再次下达，出现成功结果。已交互走查。
3. **结果不确定**：选中任意来源，点击“模拟：下达结果暂不确定”；直接点击下达被提示先查询，点击页首“查询原操作结果”后显示草稿仍可编辑。已交互走查。

原型通过本地浏览器打开与键盘 Tab 可达性作静态检查；尚未做真实浏览器、真实角色权限、接口、性能或业务数据验证。本轮按 A/B 隔离要求未做独立审查或改稿。

# 企业应用 UI 设计

把页面当作一段正在进行的工作，而不是待装饰的画布。目标是让人认得当前对象、看懂关联与状态、顺手完成下一步，进入另一页时仍沿用熟悉的操作。沿用项目的主题、组件和交互语言；技术栈由项目决定。

## 从工作顺序推导页面顺序

先看真实角色如何查找、比较、编辑和核对数据，尤其是大量数据、主从数据、关联数据与异常恢复。找到最费力的一次跳转、最难判断的一处状态。让对象关系决定信息分区，让操作入口靠近作出决定的地方；完成一个动作后，下一步应自然可见。保留已有页面教会用户的习惯，只改真正造成摩擦的部分。

## 用秩序表达轻重

空间是预算：一个区块获得宽度与注意力，别的区块就会失去它们。先排清主次、对齐和阅读路径，再处理颜色与装饰。让密集处便于比较，舒展处便于理解；留白应形成节奏，不应留下空洞。卡片、列表、表格、文字与状态表达要相互协调，既不拥挤，也不把同一信息拆成许多容器。

每段说明、每个标签和提示都应帮助用户判断、行动或恢复；说不清作用就删去。细节的价值来自业务含义，而不是元素数量。

## 在真实画面中做判断

普通页面可沿用成熟模式，仍需检查任务路径和视觉比例。复杂或有创新空间的页面，先探索不同的对象组织或操作模型，再做可交互的本地原型；把新意放在能减少寻找、切换或误判的一处，其余部分延续系统秩序。用真实数据规模与典型状态，在目标视口把原型、既有页面和候选方案并排看：主任务是否占对空间，字与间距是否有节奏，用户能否不费力地扫读和操作。让有证据的批评推动一两轮修订；新方案若不如原有结构，就保留原有结构。

请独立 [审查 SubAgent](agents/enterprise-ui-reviewer.md) 先看截图再听解释，分别裁决视觉质量与任务效果。让用户体验复杂原型并作主观判断；代理报告实际收益、代价和未验证之处，不用流程完整掩盖布局不足。方法来源见 [来源与边界](references/sources.md)。

# 数据库技能统一由 DataPull 执行

日期：2026-10-29。依据用户合并重复技能的要求实施；本决策取代 ADR-0003 和 SRS 中“旧 Skill 保持不变”的约束，保留 ADR-0005 的独立 CLI 与 ADR-0006 的唯一 Skill 源码原则。

## 对比

两者都面向 MySQL、PostgreSQL 和 SQL Server 的只读 DDL 导出。长期并存会让同一请求落到不同凭证模型、输出目录和验收规则，并要求两套导出器分别修复。

| 方面 | 原 database-schema | DataPull |
| --- | --- | --- |
| 执行实现 | Skill 内维护 Python 与 PowerShell 脚本 | 独立 Node.js/TypeScript CLI，复用官方数据库工具 |
| 连接与凭证 | 项目连接文件引用进程或 dotenv 变量 | 用户级连接登记簿，凭证由 CLI 隔离管理，跨项目复用 |
| 更新范围 | 整库快照替换 | 默认全部类型，也支持只更新指定类型；所选类型共同提交或回滚 |
| 异常恢复 | 临时目录与旧快照备份 | 事务日志、独占锁、异常中断恢复与稳定错误码 |
| 验收依据 | manifest.json、完整对象文件集 | JSON 回执中的目标、类型、计数、警告与实际 SQL 文件 |
| 维护与分发 | 导出代码和测试随 Skill 分发 | CLI 代码与测试独立维护；Skill 唯一源码同步到插件与 NPM 包 |

DataPull 的连接复用、局部更新与事务恢复更适合继续维护。旧 Skill 的优势是明确写出了结构范围、失败保护与验收要求；这些要求应进入统一流程，不必保留第二套实现。

## 决策

- 使用 `datapull` 作为唯一常规数据库导出技能，CLI 作为唯一执行入口。补齐目标精确匹配、默认全部对象、项目根路径、失败保护、计数验收和证书风险披露。
- `cli/datapull/skill/` 仍是唯一源码，使用现有 `skill:sync` 和 `skill:check` 保证插件副本一致。
- 保留 `database-schema` 的名称、目录和调用参数，调整默认提示词并设置 `allow_implicit_invocation: false`。它只处理旧参数映射并引用相邻的 DataPull Skill；插件内旧显式调用继续可用，自动选用交给 DataPull。单独复制这个兼容目录时，必须同时提供相邻的 `datapull/`。
- 移除旧 Skill 内的 Python/PowerShell 导出器、连接模板、专属参考与测试。数据库行为由 DataPull 现有测试维护，兼容入口不复制导出规则。

## 兼容范围与取舍

- 保留的是旧 `$database-schema <连接别名> <数据库名>` 的 Agent 调用入口；直接执行旧脚本路径的方式停止支持，需要改用 DataPull CLI。
- 旧项目级连接不会自动导入用户级 CLI 登记簿。用户通过 CLI 重新登记，Agent 不读取秘密文件或搬运凭证。
- 新文件位于 `.database-schema/<连接别名>/<数据库名>/`，旧文件位于 `.database-schema/schemas/<连接别名>/<数据库名>/`。旧目录与配置原样保留；使用方若依赖旧路径，需要自行调整。
- DataPull 不生成旧 manifest，不保证旧文件格式，也不把不同时间更新的对象类型称作同一时点的完整快照。结果以实际 JSON 回执和所选类型的文件校验为准。
- 保留 CLI 缺失时由用户执行全局安装的边界；数据库工具安装和证书信任沿用已授权范围，不因技能合并扩大权限。

## 验证与回滚

检查技能格式、命名与引用，确认兼容入口不被隐式选择且插件副本与唯一源码一致。运行 DataPull 静态检查、既有单元/集成测试与构建；这些验证不代表真实数据库或已安装插件验收。

回滚时恢复本次技能与文档变更，再同步 DataPull Skill。此次合并不修改数据库、用户连接登记簿或已有结构文件，无需数据迁移。

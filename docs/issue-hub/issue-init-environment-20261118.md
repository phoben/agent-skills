# Issue 初始化环境检测验收

日期：2026-11-18，东八区。实现基于 `main` 的 `1e16bf1`，工作分支 `codex/issue-init-doctor`。

## 能力变化

`issue-init` 现在从目标项目现状开始，按“检测 → 选择方案 → 按授权补齐环境和规则 → 复检 → 行为验收”引导。没有 Issue、合同、Git 或 Trellis 均可开始；Trellis 为可选方案，已有流程优先复用。

新增共享工具入口：

```text
node <issue-triage技能目录>/scripts/issue-tools.mjs doctor --root <项目>
node <issue-triage技能目录>/scripts/issue-tools.mjs doctor --root <项目> --workflow trellis --platform codex --remote
```

默认只做本地诊断；`--remote` 只通过已有 gh 读取目标仓库与完整分页标签。连接器、共享 Type／字段、精确管理权限及当前宿主启用状态由主会话实际核实。诊断不执行安装、登录、初始化、项目写入或 GitHub 写入，也不把命令成功当作完整接入。

`readiness` 分别记录本地、GitHub 和行为状态，未知必要项不会标为就绪；`complete:false` 说明工具不证明整体完成。主会话根据额外检查及真实入口验收给出最终结果，缺人工步骤时保留待办和继续入口。

用户选择并批准 Trellis 后，技能指导主会话使用官方安装／初始化／更新入口补齐，不手工复制原生文件或改哈希。没有任何流程且选择精简方案时，先根据实际角色、批准和验收习惯建立规则，再接入 Issue 合同。

## 三个技能试用场景

1. **只有代码的空白项目**：没有要求先提供 Issue 或合同，没有安装工具；用业务案例询问精简流程或 Trellis，再确认仓库与规则。
2. **已有非 Trellis 流程**：实际阅读批准、实施、测试和验收约定，建议沿用现有流程，下一步核对目标仓库，无须迁移 Trellis。
3. **残缺 Trellis**：识别只有目录／workflow 不代表接入完成，列明缺失核心、原生技能及平台注册；目录发现结果不冒充用户选择，先确认保留并补齐还是采用精简规则。

这是独立子 Agent 的真实技能试用，不是三次独立宿主冷启动。没有执行真实安装、登录、远端标签写入或完整新项目初始化；远端行为测试使用注入的只读回放，不证明实际账号权限。试用另读取本机 Trellis 帮助和模板目录，未做 CLI 内部缓存／网络来源的网络级审计。

原始诊断、命令、试用答复、夹具基线、哈希和日志保留在恢复工作区忽略目录 `.tmp/issue-init-doctor-tests/`，未分发真实业务内容或凭据。

复验运行两个共享脚本的 `node --test`、两个模块的 test、统一 build、双 verify:stdio 及 verify:toolkit。原生集成需目标项目实际 hook 注册、已审核 workflow 和保护基线；它只在临时夹具写任务与状态，真实项目保持只读。

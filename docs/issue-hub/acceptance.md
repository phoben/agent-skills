## 验收中修复的问题

缓存恢复后目录仍待核对，曾阻断创建任务；现在显式准备主动刷新并显示进度。保存或核对期间切换上下文会停止旧动作。

已发送聊天曾被 projectId 筛选排除，消息包装也与旧夹具不一致；现在保持精确 cwd、身份、首条完整唯一引用及覆盖保护，正确解析官方包装。

附件/PR 空态、活动首批及后页更新曾有缺口；已补状态说明、去重和局部更新，并保留评论/表单与焦点。上述问题均建立先红后绿回归，未按标题或时间猜测关联。

## 仍保留的边界

- 第二台真实 Windows、成员自己的 gh/组织授权和基本业务路径未验收，待设备到位后按[交接清单](windows-handoff.md)执行。
- 原生多工作区另建和操作系统整体断网画面未单独实测；相关逻辑有 Git/worktree、控制器及传输验证。
- 发现仍可能因无效目录或扫描边界标为 partial，不保证全盘无界发现。
- GitHub 无通用原子 CAS，检查到写入之间存在竞争窗口。
- 历史对话、请求标识、缓存、原型截图、CLI 临时目录及本机执行日志仅留本地，未作为插件内容发布。以上为汇总验收结论，不能反推每个分支都在原生 UI 实测。

构建和重复验证命令见[包说明](../../packages/issue-hub/README.md)。正式发布及团队第二机验收分别执行。

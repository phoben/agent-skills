# 系统宣传视频生成 Skill 可行性调研

**调研日期：**2026-09-19  
**范围：**在 YG Toolkit 中新增“系统宣传视频生成”Skill 的产品可行性、外部能力接入和交付边界。本文只把厂商官网、官方 API 文档、官方公告，以及本机可观察的 Codex 插件清单作为事实依据；“可接入”不等于“已经在本机会话中可用”。

## 结论

**可以构建，建议立项；但不能把目标定义为“一句话稳定生成任意风格、任意形式、无需审核的高品质成片”。**

现实可交付的能力是一个“受控的宣传片生产流水线”：Skill 把系统事实、品牌资产、可验证的界面录屏/截图、分镜和配音稿组织起来，按镜头调用可替换的视频供应商，执行自动质检和人工关卡，最后合成并交付可追溯的成片。模型的进步已经使短镜头、参考素材约束、原生音频、延展与编辑成为可编排能力；稳定性则来自生产流程，而非某一个模型。

建议首版承诺：30–60 秒、横版/竖版、三类模板（产品功能介绍、品牌故事、活动/社媒短片），以真实系统录屏、产品图和品牌素材为主体，AI 用于 B-roll、氛围镜头、转场和概念表达。全 AI 剧情、跨镜头人物完全连续、中文界面/Logo/小字准确渲染、长篇口型对白均应列为“需人工验收”的增强项，不能写进稳定性承诺。

## 本机插件与接入事实

截至调研日，本机插件缓存中可以确认存在 **Visla Video Maker** 与 **Explain Video Generator** 的应用包，但 `codex plugin list` 没有把它们列为当前已启用插件，本会话也没有暴露对应的可调用工具。因此这里只能确认“本地存在插件包”，不能确认已经连接账号、具有生成权限或能够下载成片。当前会话确实提供 `superdesign` Skill；其 CLI 可以实时列出视频模型并创建免费报价，但它首先是设计资产工作流，不是已经验证过的批量成片流水线。本机 `codex plugin list` 访问远程市场时收到 403，因此不能以这一次枚举否定市场中其他候选。

本次现场调用 `Superdesign CLI` 得到 5 个视频模型：`Seedance 1 Pro Fast`、`Seedance 1 Pro`、`Seedance 2.0`、`MiniMax Hailuo 2.3 Fast`、`MiniMax H3`。其中当前套餐只可直接使用 `Seedance 1 Pro Fast` 的 480p 档；`Seedance 2.0` 与 `MiniMax H3` 均显示需要升级，目录中没有 `Seedance 2.5`。CLI 已具备很有价值的付费安全契约：先免费报价并返回精确积分，再经用户明确确认后生成；确认任务支持幂等恢复。未来 Skill 可以复用这个模式，但不能把目录中出现的模型写成“当前已获生成授权”。

用户提供的市场候选中包含 **Runway** 和 **Higgsfield**；这仅证明候选入口在当前市场列表中出现，不能推出账户已安装、已授权、可用模型、价格或导出权限。**Visla、Explain Video** 虽有本地应用包，但当前会话不可调用，故同样不把它们作为首版硬依赖；后续启用时必须按实际工具契约重新验收。每个插件入口也只代表该插件公开的能力，不能外推为厂商全平台能力。

可作为首版技术主线的是直接 API 或有明确 API 的聚合平台，而不是依赖聊天式插件：Google Gemini API、Runway Dev、Adobe Firefly API 均有官方开发文档。这样才可做异步任务、失败重试、成本计量、审计和供应商切换。

## Skill 的正确产品边界

这个 Skill 应是“编导、生产控制和验收器”，而不是假装自己是视频模型。建议架构如下：

```text
业务简报/系统事实/品牌包/真实界面素材
             ↓
  事实校验 + 脚本/分镜 + 风格模板 + 合规检查
             ↓
  镜头合同（时长、比例、主体、动作、音频、禁用项、参考资产）
             ↓
  供应商适配器（Seedance / Veo / Runway / Firefly，可替换）
             ↓
  多候选生成 → 自动硬规则质检 → 人工镜头批准
             ↓
  非生成式合成（录屏、字幕、配音、音乐、转场、转码）
             ↓
  成片 + 项目清单（素材授权、模型版本、提示、成本、验收记录）
```

### 必须固化的生产约束

- **事实优先：**系统功能、权限、业务数据只能取自仓库、运行界面和获准素材；不可让模型虚构功能、客户、指标或合规承诺。
- **UI 不交给视频模型重画：**中文界面、报表数字、Logo、小字号 CTA 应来自真实录屏、静态图层或后期字幕；模型只生成它擅长的视觉运动。
- **镜头而非整片：**每条生成任务只对应一个有验收标准的短镜头；长片由已批准镜头、录屏、音频和时间线合成。
- **品牌包和素材授权：**每次生产显式登记 Logo、色彩、字体、角色/产品参考、音乐/肖像授权及敏感内容禁用项；禁止把未获授权的人脸、客户数据传到供应商。
- **供应商可替换：**能力注册表须记录模型版本、地区、账户权限、输入/输出、时长、音频、参考、配额、单价、保留期、失败码和淘汰日期；每次生成保存实际使用版本。
- **费用和安全关卡：**在付费调用前确认账户、预算上限、地区、素材数据处理和导出权；任何未拿到生成任务与下载回执的“成功”都不算交付。

## 验收：怎样才叫“稳定高品质”

不要用一次演示成功替代稳定性。首版应把“稳定”拆为可测的指标，并按品牌模板、比例和供应商分别统计：

| 层级 | 最低验收指标 | 不通过时的动作 |
| --- | --- | --- |
| 任务可靠性 | 创建、轮询、下载、归档全链路成功率；超时、429、内容拦截、供应商失败分类可见；有幂等键和指数退避。 | 自动重试在预算内；仍失败则切换供应商或人工处理。 |
| 镜头技术质量 | 时长、比例、帧率、分辨率、音轨、无黑帧/损坏文件均符合镜头合同。 | 自动拒绝。 |
| 品牌与事实 | 正确 Logo/字体/色彩、无虚构功能或数据、UI 来自真实证据。 | 自动规则拦截加人工复核。 |
| 视觉连续性 | 主体、服装、产品、色调、镜头运动与参考图和前后镜头一致；人工评分达到预设门槛。 | 重生成或改用真实素材/后期。 |
| 声画与文案 | 配音、字幕、音乐节奏准确；中文专名和 CTA 经人工校对。 | 以 TTS/后期字幕修正，不能依赖视频模型重绘文字。 |
| 发布合规 | 素材权属、人物授权、平台政策、AI 标识/水印与客户审批记录齐全。 | 禁止发布。 |

建议先做一个受控基准集：每个模板至少覆盖横版、竖版、无人物、单人物、含真实 UI、含中文配音六类场景；每个供应商/模型版本以固定镜头合同重复生成，记录通过率、人工返工率、平均成本和交付耗时。达到门槛后才扩展风格与时长。Seedance 2.0、Veo 和 Firefly 官方文档都明确存在安全过滤、输出限制或尚待改进项，这也是把人工批准保留在流程中的依据。

## 分阶段建议

1. **调研后的 POC（先验证，不承诺对外成片）：**选一个有合法凭证的主供应商和一个备选供应商；以同一 20–30 秒系统介绍样片测试横/竖版、参考图人物/产品、中文配音、真实 UI 合成、下载回执和成本。
2. **MVP Skill：**生成项目目录、事实来源表、品牌包、脚本/分镜、镜头合同、供应商任务清单、质量检查单和最终交付清单；成片合成使用可复现的本地时间线，不自动发布。
3. **生产试运行：**固定三种模板与审批角色，累计基准集数据；接入队列、预算阈值、供应商降级和可追溯日志。
4. **再扩展：**在每个新增模型/风格通过同一基准集后，加入更长叙事、人物故事、复杂编辑或批量多版本投放；仍保留人工发布关卡。

## 最终建议

为 YG Toolkit 新建此 Skill 是合理且有产品价值的，名称宜体现边界，例如 `system-promo-video`，定位为“基于真实系统证据和品牌资产的宣传片生产与验收”。首版不要绑定某个聊天插件或单一模型；优先实现供应商适配、镜头合同、质检与可追溯交付。Seedance 2.5 应进入优先 POC 候选，但其字节官方 API 可用性须在取得真实访问权限时再验收；Runway 可作为聚合/备选入口，Veo 适合可编程短镜头，Firefly 适合人工精修。这样才能在模型、价格、地区和 API 持续变化时仍维持对外可控的交付质量。
